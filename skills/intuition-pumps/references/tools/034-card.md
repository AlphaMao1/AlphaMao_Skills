## 名称与思想实验

“万能酸”是丹尼特用来比喻达尔文思想的画面：假设有一种酸能腐蚀任何容器，玻璃瓶、不锈钢罐、纸袋都挡不住它。问题随之出现：你该怎样盛放它？如果它流出来，会不会一路腐蚀整个世界？它经过之后还会留下什么？

丹尼特说，达尔文的自然选择观念就像这种万能酸。它会侵蚀许多传统概念的保护壳：设计、目的、价值、伦理、艺术、文化、宗教、情绪、意识等都不能再简单藏在神秘隔离区里，声称自己免受自然解释审查。但这不是说达尔文思想把这些珍贵事物毁掉，而是说它会改写它们的基础：把意义、目的和设计感锚定到变异、筛选、保留、复制和累积历史中。

因此 `/万能酸` 的动作不是粗暴地说“这不过是进化”。它要求把某个看似需要设计者、本质或目的的复杂性放进达尔文式机制中检查：有什么变异，什么压力筛选，优势如何保留和复制，每个中间阶段是否有局部收益。只有这条链走通，万能酸才是解释工具；否则只是把“自然选择”当成另一层神秘词。

## 原书机制转译

这个工具处理“复杂性必须来自设计者、本质、目的或神秘跳跃”的直觉。达尔文式解释会腐蚀这种直觉：设计感可以来自无心选择，目的感可以来自历史筛选，复杂结构可以由小差异在保留和复制中逐步累积。

`/万能酸` 的机制不是把“自然选择”当口号，而是逼你回答五个问题：变异从哪里来，选择压力是什么，什么单位被保留或复制，优势如何累积，中间阶段是否可行。只有这些环节都有具体机制，达尔文式解释才真正工作。

它可用于生物演化，也可谨慎用于文化、组织流程、产品习惯、语言用法和市场策略等存在变异、筛选、保留和复制的系统。

## 用户模式

### 触发场景

- 有人说某种复杂性必须来自设计者、本质、目的或神秘跳跃。
- 一个结构看起来“像被设计过”，但可能有累积选择路径。
- 你要解释某个习惯、流程、制度、语言用法或策略为什么会变得精巧。
- 你想检查“自然选择/市场选择/文化选择”是不是空话。

### 操作步骤

1. 写出待解释的复杂性或设计感。
2. 找变异来源：哪些版本会自然出现，差异从哪里来。
3. 找选择压力：环境、用户、成本、竞争、奖励、惩罚如何筛选版本。
4. 找保留机制：有利版本如何被保存下来。
5. 找复制机制：有利版本如何传播、复用或遗传。
6. 找中间阶段：每一步是否都有局部好处，而不是必须一次成型。
7. 判断是否还需要天降式解释，或只是还缺某个选择环节。

### 输出结构

```text
待解释复杂性：

达尔文五问：
1. 变异来源：
2. 选择压力：
3. 保留机制：
4. 复制机制：
5. 累积路径：

中间阶段是否可行：
还缺的机制：
结论：
```

## agent 自救模式

### 卡住信号

- 我把复杂性解释成“有人设计/本质如此/自然选择”但没有机制。
- 我说“它被筛选出来”，却没有选择单位。
- 我没有说明有利差异如何被保留和复制。
- 当前解释要求复杂结构一次性出现。

### 自救动作

1. 抽出复杂性对象。
2. 回答达尔文五问。
3. 检查中间阶段是否各自有局部收益。
4. 如果某环节缺失，标为缺口，不用“选择”糊过去。
5. 只在机制完整时保留选择解释。

### 轻量输出

```text
工具：/万能酸
当前卡点：我可能把复杂性归给设计者、本质或空泛选择。
本工具给出的拆分：变异来源 / 选择压力 / 保留机制 / 复制机制 / 累积路径。
下一步：确认每个中间阶段都有可保留的局部优势。
```

## 误用边界

- 不要把“自然选择”当空话。没有明确选择单位和机制，就只是贴标签。
- 不要把所有复杂性都解释成选择结果。有些复杂性来自直接设计、物理约束、随机漂变或历史偶然。
- 不要把结果倒推成目的。选择可以产生目的感，但过程本身不需要预见终点。
- 不要跳过中间阶段。每一步都要说明为什么能存在、保留或传播。

## 小测试问题

请用 `/万能酸` 对“一个团队逐渐形成高质量代码评审习惯”写达尔文五问：变异、保留、选择、复制、累积路径。

## 测试运行结果

待解释复杂性：

一个团队形成了高质量代码评审习惯：评审意见具体、关注风险、要求测试、避免人身攻击，并且新成员也会学会这种风格。

达尔文五问：

1. 变异来源：
   不同成员最初会用不同方式评审：有人只看格式，有人看 bug，有人问需求，有人写很尖锐，有人给可执行建议。不同项目、事故和新人加入也会带来新评审风格。

2. 选择压力：
   能提前发现 bug、减少返工、让 PR 更快合入、降低线上事故的评审方式，会得到团队正反馈。空泛、攻击性强、只纠结偏好的评审方式，会被反感、忽略或被负责人纠正。

3. 保留机制：
   有用评论被复制到模板、评审清单、团队规范和示例 PR 中；资深成员会在后续评审中重复同类问题；事故复盘会保留某些检查项。

4. 复制机制：
   新成员通过阅读历史 PR、模仿资深成员、使用评审模板、接受反馈，把有效评审风格复制到自己的行为中。

5. 累积路径：
   第一阶段只形成“看测试”的习惯；第二阶段加入“看边界条件”；第三阶段加入“看需求意图”；第四阶段加入“表达要具体且尊重人”；第五阶段沉淀成模板、培训和自动检查。

中间阶段是否可行：

可行。每一阶段都有局部收益：看测试减少回归；看边界减少线上事故；看需求意图减少错做；表达具体提高合入效率；模板让收益更稳定。

还缺的机制：

需要确认团队确实有反馈和保留渠道。如果没有事故复盘、模板、资深示范或新人训练，习惯可能无法稳定复制。

结论：

这个复杂评审习惯不必一次性由某个设计者完整发明。它可以由多种评审变异在团队反馈、保留、复制和累积中形成。但如果没有明确保留和复制机制，“文化选择”就只是标签。

测试结论：通过。本工具用达尔文五问解释了复杂习惯的累积形成，并标出了选择解释需要的具体机制。
