# 011 反问还原

## 身份

- 原书标题（中文）：反问：让你不好意思说“不”
- 英文原名：Rhetorical Questions
- 中文标题来源：书内译名 + 自拟功能副题。短命令“反问还原”和卡片标题“把问号还原成断言”是 skill 化后的操作性改写。
- 原书分组：第一部分 通用思考工具
- 中文短命令：/反问还原
- 别名：11、工具11、反问、反问：把问号还原成断言
- 工具家族：论证检验
- 默认输出重量：轻到中等。输出反问改写、可能否定回答、作者是否排除该回答。
- 对应 issue：ISSUE-020 / TOOL-011

## 名称与思想实验

“反问”这张工具和“小心当然”紧挨着，因为它们都在论证里制造一种显然性压力。反问表面上有问号，实际上不是真的在等回答；它暗示答案已经明显到正常人不好意思说“不”。这就是中文标题里“让你不好意思说不”的意思。

丹尼特把反问看成一种压缩版的归谬法：作者省掉了推理链，只留下“这还用问吗”的社交压力。原书用《花生漫画》的小场景说明这个机制：查理·布朗发出一个关于谁能判断对错的反问，露西却认真给出一个出人意料的回答。笑点就在于，反问一旦被当成真问题，它的魔法就失效了。

所以“反问还原”的操作是：不要急着接受问句预设的答案，先把问号改成陈述句，再写出一个合理的“不，因为……”。如果这个否定回答没有被作者排除，反问就不能承担证明重量。

## 原书机制转译

这个工具解决的是反问带来的推理短路。反问表面上是问题，实际上常常不期待回答，而是在暗示“正常人都不会反对”。它把本来需要证明的断言包装成社交压力，让读者不好意思说“不”。

`/反问还原` 的机制是把问号去掉，把反问改成陈述句，再主动写出一个可能的否定回答。只要否定回答还没有被排除，反问就不能承担关键证明。

## 用户模式

### 触发场景

- 文章或争论中出现明显不期待回答的问句。
- 某个问句让人觉得“不这样想就很荒唐”。
- 反问承担了关键证明，而不是普通修辞。
- 你需要把情绪压力还原成可检验断言。

### 操作步骤

1. 摘出反问句。
2. 把它改写成陈述句。
3. 写出一个可能的否定回答：`不，因为……`
4. 检查作者是否已经排除这个回答。
5. 如果没有排除，把反问标为情绪施压或论证缺口。
6. 如果已经排除，则把它当作修辞，不把问题夸大。

### 输出结构

```text
原反问：
还原成断言：
可能回答：不，因为……
作者是否排除这个回答：
判断：修辞 / 情绪施压 / 论证缺口
```

## agent 自救模式

### 卡住信号

- 我被一个问句推着默认回答“当然是”。
- 我没有检查反问是否承担证明。
- 我觉得反对某句话会显得荒唐，但还没看到证据。
- 用户要求拆解争论中的情绪性问句。

### 自救动作

1. 把反问改成断言。
2. 写一个合理的“不，因为……”。
3. 查这个否定回答是否被排除。
4. 若未排除，标出论证缺口。

## 误用边界

- 反问可以作为修辞，但不能承担关键证明。
- 不要因为有问号就过度审查。只有不期待回答、且承担论证重量时才需要处理。
- “我可以回答不”不代表反问一定错；还要看作者是否已有理由排除这个回答。
- 不要把这个工具变成抬杠。目标是恢复可回答性。

## 小测试问题

请用 `/反问还原` 检查这句话：“难道为了效率，不应该先一次性生成 77 张工具卡吗？”

## 测试运行结果

原反问：

难道为了效率，不应该先一次性生成 77 张工具卡吗？

还原成断言：

为了效率，应该先一次性生成 77 张工具卡。

可能回答：

不，因为这个项目的关键风险不是写得慢，而是每张工具卡如果没有逐个理解和测试，就会变成模板填空。

作者是否排除这个回答：

没有。反问只强调效率，没有处理“批量生成会破坏逐卡转译质量”这个反对理由。

判断：

论证缺口。这个反问不能证明“一次性生成”合理，它只是让反对者看起来像不重视效率。

测试结论：通过。本工具把反问还原成断言，给出可回答的否定理由，并检查原句是否排除了该理由。
