# 040 白蚁设计

## 身份

- 原书标题（中文）：白蚁城堡是谁设计的：无需理解的能力之二
- 英文原名：Free-Floating Rationales
- 中文标题来源：书内译名 + 书内副题。卡片标题“没有建筑师也可以有设计”是 skill 化后的功能副题。
- 原书分组：第五部分 关于进化论的思考工具
- 中文短命令：/白蚁设计
- 别名：40、工具40、白蚁城堡是谁设计的、白蚁城堡是谁设计的：没有建筑师也可以有设计
- 工具家族：进化机制
- 默认输出重量：中等。输出局部规则、反馈循环、整体结构、保留机制和中央设计师检查。
- 对应 issue：ISSUE-049 / TOOL-040

## 名称与思想实验

“自由浮动的理据”是丹尼特给进化理由取的名字。自然选择没有心智，不能表述理由，却能在许多代中保留那些“有理由”存在的差异：某种结构更稳、更省能、更能繁殖、更能保护后代，于是相关变异被保留。理由先存在于选择关系中，后来才被人类或其他有心智的系统说出来。

原书用白蚁城堡和高迪的圣家族大教堂作对照。两者外形都很精巧，也都可以问“为什么这样建”。圣家族大教堂的结构理由主要是高迪和工程团队能表达的理由；白蚁城堡的通风、保温和形状也有理由，但没有哪只白蚁是建筑师，也没有哪只白蚁知道整体蓝图。理由在结构和环境的关系中发挥作用，却不被白蚁拥有。

因此 `/白蚁设计` 不只是说“没有中央设计师”。它要求使用者把整体功能、局部规则、反馈和保留机制写清楚，同时区分两句话：这个结构有理由；参与者是否拥有或理解这些理由。自由浮动的理据不是幽灵，更像重心或数：在我们命名和表达之前，相关关系已经在世界中起作用。

## 原书机制转译

这个工具处理“精巧整体结构一定需要中央设计师”的直觉。集体结构可以有功能理由，但个体不必理解这些理由，也不必有一个全局蓝图。局部规则、局部反馈、环境信号和长期选择可以产生设计感。

`/白蚁设计` 的机制是从底层互动往上解释整体结构：个体各自遵循哪些简单规则，局部行为如何互相影响，环境如何反馈，哪些结构被保留，最终整体功能如何出现。它适合分析巢穴、市场、城市、开源生态、语言演化、组织流程和社群规范。

它和 `/能力先于理解` 相邻，但焦点不同：`/能力先于理解` 看个体能力和理解的关系；`/白蚁设计` 看多个个体或组件如何共同生成有设计感的整体结构。

## 用户模式

### 触发场景

- 集体结构精巧，像蚁巢、市场、城市、开源生态、语言演化。
- 有人想寻找一个不存在的中央设计师。
- 你需要解释局部规则如何产生整体秩序。
- 你要区分“无中央设计”和“无功能解释”。

### 操作步骤

1. 写出整体结构及其功能。
2. 列出个体或组件的局部规则。
3. 列出个体之间、个体与环境之间的反馈。
4. 描述整体结构如何从局部互动中出现。
5. 解释该结构为什么被保留、复制或强化。
6. 检查是否真的需要中央设计师。
7. 标出局部规则失效时整体结构如何崩坏。

### 输出结构

```text
整体结构：
整体功能：

局部规则：
反馈机制：
涌现路径：
保留机制：
是否需要中央设计师：
失效边界：
```

## agent 自救模式

### 卡住信号

- 我看到整体秩序，就默认有中央规划。
- 我说“自组织”，但没有局部规则和反馈机制。
- 我把无中央设计误写成无目的、无功能。
- 当前解释只描述整体形状，没有说明保留机制。

### 自救动作

1. 抽出整体功能。
2. 写局部规则和局部反馈。
3. 写整体结构的形成路径。
4. 写保留或强化机制。
5. 判断是否还需要中央设计者。

### 轻量输出

```text
工具：/白蚁设计
当前卡点：我可能把整体设计感归给中央设计师。
本工具给出的拆分：整体功能 / 局部规则 / 反馈机制 / 涌现路径 / 保留机制。
下一步：解释无中央设计如何仍有功能结构。
```

## 误用边界

- 无中央设计不等于无功能解释。
- 不要把“涌现”当空词。必须写局部规则和反馈。
- 不要否认真实规划的存在。城市、平台和组织常常既有局部涌现，也有局部规划。
- 不要把个体理解强加给整体。个体不必理解整体功能，整体仍可能有功能。

## 小测试问题

请用 `/白蚁设计` 比较“白蚁城堡/城市交通/维基百科”三者的局部规则和整体结构。

## 测试运行结果

| 案例 | 整体结构/功能 | 局部规则 | 反馈机制 | 是否需要中央设计师 |
| --- | --- | --- | --- | --- |
| 白蚁城堡 | 通风、保温、防护和居住结构 | 个体搬运材料、响应气味/湿度/局部形状、在特定信号附近堆放 | 局部结构改变气流和湿度，反过来影响后续堆放行为；不良结构不稳定或不利生存 | 不需要一个懂建筑蓝图的个体；整体结构可由局部行为和选择保留产生 |
| 城市交通 | 道路流量、拥堵模式、通勤路径、商业区形成 | 个体选择路线、避开拥堵、靠近工作和服务点，平台提供导航 | 拥堵改变路线选择，商业和居住分布改变交通需求，规则和基础设施又反馈到行为 | 不完全需要中央规划；但现实中常混合了规划、市场和个体选择 |
| 维基百科 | 大规模知识条目和编辑规范 | 个体新增、修订、引用、撤销、讨论、遵守格式 | 错误被回退，高质量条目被保留，规范通过争议和模板传播 | 不需要单一总编辑写完整百科；但需要平台规则、社群治理和技术设施 |

涌现路径：

三者都不是由单个全局理解者一次设计完成。局部行为在反馈中被重复、修正和保留，逐渐形成整体结构。

保留机制：

稳定巢穴提高群体存活；交通路径由成本和效率筛选；百科条目由引用、编辑、社群规范和可见质量保留。

失效边界：

如果局部规则错误、反馈延迟过长、纠错机制失效，整体结构会退化：巢穴坍塌、交通拥堵恶化、百科质量下降。

结论：

没有中央设计师并不意味着没有设计感。整体功能可以来自局部规则、环境反馈和长期保留机制。

测试结论：通过。本工具比较了三个集体结构，说明局部规则和反馈如何生成有功能的整体设计感。
