# 044 物种形成

## 身份

- 原书标题（中文）：物种形成于何时：某个精确但又不为人知的时刻
- 英文原名：When Does Speciation Occur?
- 中文标题来源：书内译名 + 书内副题。卡片标题“把事件地位和当时事实分开”是 skill 化后的功能副题。
- 原书分组：第五部分 关于进化论的思考工具
- 中文短命令：/物种形成
- 别名：44、工具44、物种形成于何时、物种形成于何时：把事件地位和当时事实分开
- 工具家族：概念澄清
- 默认输出重量：中等。输出过程节点、当时事实、后来地位、当前用途和节点选择。
- 对应 issue：ISSUE-053 / TOOL-044

## 名称与思想实验

“物种形成于何时”延续 043 的边界问题，但更关注历史事件的地位。原书设想：未来某种灾难后，智人只剩两个彼此隔离的小群体，一个在北方岛屿，一个在印度洋孤岛。它们分开生活上万年，逐渐适应不同环境，最终再次相遇时不再愿意或不能成功交配，于是被看作两个物种。

问题是：物种形成事件到底发生在哪一天？最近共同祖先可能生活在更早年代，但那不是物种形成发生的时刻；两群人最初分离时，也还不能确定这一分离会不会导致物种形成，因为任何一次早期重聚都可能取消这个未来。某次具体出生也许后来会被追认为关键节点，但它的特殊地位只有在几千年后后果展开时才成立。

因此 `/物种形成` 要求使用者区分“当时发生了什么”和“后来被赋予什么地位”。历史过程常有多个候选节点：隔离、差异积累、生殖隔离、不可逆后果、后人命名。不同问题需要不同节点，不必假装存在一个当时自带标签的神秘瞬间。

## 原书机制转译

这个工具处理“历史过程中的精确转折点”问题。有些事件不是在当时挂着标签发生的瞬间，而是在后果展开后才获得特殊地位。物种形成、平台形成、文化形成、技术范式形成，往往是过程，不是单点。

`/物种形成` 的机制是把一个“何时成为 X”的问题拆成多个节点：过程开始、隔离形成、差异积累、关键功能出现、不可逆结果、后人命名。然后问：当前问题真正需要哪个节点？这样可以避免寻找一个神秘瞬间，也能避免把后来叙事投回当时事实。

这张卡适合处理历史、组织、产品、科学发现、制度变化和演化过程中的“什么时候算”。

## 用户模式

### 触发场景

- 你想找历史过程中的精确转折点。
- 某件事后来很重要，但当时未必显得重要。
- 争论在“到底是哪一天成为 X”上卡住。
- 你需要区分过程开始、差异积累、结果不可逆和后人命名。

### 操作步骤

1. 写出“何时成为 X”的问题。
2. 列出过程节点：开始、隔离、差异积累、功能出现、不可逆、命名。
3. 对每个节点写当时可观察事实。
4. 写后来为什么给该节点特殊地位。
5. 判断当前任务需要哪个节点：因果解释、法律生效、叙事、教学、分类、决策复盘。
6. 选择最有用节点，并说明它不是唯一神秘瞬间。
7. 给出多节点时间线。

### 输出结构

```text
问题：

| 节点 | 当时事实 | 后来地位 | 对当前问题是否有用 |
| --- | --- | --- | --- |

当前问题需要的节点：
不应寻找的神秘瞬间：
结论：
```

## agent 自救模式

### 卡住信号

- 我想找唯一转折点，但过程明显分阶段。
- 我把后来的命名和当时事实混在一起。
- 我没有说明为什么某个节点对当前问题有用。
- 我把连续过程写成戏剧性瞬间。

### 自救动作

1. 列出至少五个候选节点。
2. 分开当时事实和后来地位。
3. 说明当前用途。
4. 选择有用节点而非唯一真点。
5. 明确其他节点仍可能对别的问题有用。

### 轻量输出

```text
工具：/物种形成
当前卡点：我可能在过程里寻找唯一神秘时刻。
本工具给出的拆分：过程开始 / 差异积累 / 关键功能 / 不可逆结果 / 后人命名。
下一步：按当前问题选择有用节点，并分开当时事实和后来地位。
```

## 误用边界

- 存在连续过程，不代表有一个唯一且重要的精确时刻。
- 不要把后来命名投射成当时自带标签。
- 不要用过程性否认节点分析。不同任务可以需要不同节点。
- 法律、合同、系统事件可能有明确生效时刻；那要尊重外部标准。

## 小测试问题

请用 `/物种形成` 拿“创业公司何时成为平台”做类比，列五个可能节点。

## 测试运行结果

问题：

这家创业公司何时成为平台？

| 节点 | 当时事实 | 后来地位 | 对当前问题是否有用 |
| --- | --- | --- | --- |
| 产品上线 | 公司发布第一个可用产品 | 后来被视为平台前史起点 | 对叙事有用，但不等于已经是平台 |
| 第一批第三方供给者加入 | 不再只有公司单方提供内容或服务 | 形成双边结构的早期信号 | 对平台机制分析很有用 |
| 网络效应开始可测 | 新用户或供给者的加入提高另一侧价值 | 平台属性开始产生独立动力 | 对商业模型判断很有用 |
| 规则和接口开放 | 公司提供 API、规则、分成、审核机制 | 外部参与者可以稳定围绕它建设 | 对生态形成判断很有用 |
| 离开单个核心产品仍能运转 | 多类参与者、工具和交易在规则内自我循环 | 后来被加冕为“平台化成功” | 对是否已经成熟平台有用 |
| 媒体或投资人称其为平台 | 外部叙事改变 | 命名发生，但未必改变底层事实 | 对传播和融资有用，对机制判断有限 |

当前问题需要的节点：

如果讨论商业机制，应选“网络效应开始可测”和“规则接口开放”。如果讨论公司叙事，可以选“产品上线”。如果讨论成熟度，应选“离开单个核心产品仍能运转”。

不应寻找的神秘瞬间：

不该问“哪一天它真正变成平台”而不说明用途。平台地位是多个过程叠加后形成的。

结论：

“成为平台”不是单一瞬间。不同问题需要不同节点：起点、机制出现、生态稳定、外部命名都可能有用，但不能混为一个神秘转折点。

测试结论：通过。本工具把“何时成为平台”拆成多个候选节点，并分开了当时事实和后来地位。
