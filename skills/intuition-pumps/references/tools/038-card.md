# 038 起重机天钩

## 身份

- 原书标题（中文）：自然选择VS智能设计：“起重机”VS“天钩”
- 英文原名：Natural Selection versus Intelligent Design: "Cranes" versus "Skyhooks"
- 中文标题来源：书内译名 + 书内副题。卡片标题“找起重机，不找天钩”是 skill 化后的功能副题。
- 原书分组：第五部分 关于进化论的思考工具
- 中文短命令：/起重机天钩
- 别名：38、工具38、自然选择 VS 智能设计、自然选择 VS 智能设计：找起重机，不找天钩
- 工具家族：进化机制
- 默认输出重量：中等。输出复杂性差距、天钩嫌疑、起重机机制、中间阶段和保留条件。
- 对应 issue：ISSUE-047 / TOOL-038

## 名称与思想实验

“起重机”和“天钩”是丹尼特用来区分两类复杂性解释的工程比喻。生命中的精巧结构需要大量研发，不可能只是纯偶然；问题是研发从哪里来。天钩是悬在空中的神奇升降装置，好像能把复杂性从天上直接吊下来：神秘设计者、不可解释的天才、本质力量、一次性奇迹，都可能扮演这种角色。它看起来解决问题，实际上常把复杂性来源后移。

起重机不同。起重机也能“提升”重物，但它有地基、材料、搭建过程和成本；小起重机还可以搭起更大的起重机。达尔文自然选择就是最基本的起重机：从早期可复制实体出发，靠小变异、局部收益、保留和复制，在极长时间里逐渐穿越设计空间。后来还会出现新的起重机，如共生、有性繁殖、基因工程、学习和文化传递，它们本身也需要解释为先前过程的产物。

因此 `/起重机天钩` 的动作是审查解释有没有“凭空吊起”复杂性。凡是说“因为有设计者/天才/本质，所以复杂结构出现了”，都要继续追问：这个设计者或能力自身如何形成？有没有可落地的中间步骤？有没有每一步的保留条件？真正好的解释应当把天钩替换成一个或多个能逐步搭建复杂性的起重机。

## 原书机制转译

这个工具处理巨大复杂性差距。天钩是从天而降的神奇解释：有一个设计者、本质、灵光或外部力量直接把复杂性吊起来。起重机则是低层过程一步步搭建复杂性的机制：每一步都能由前一步到达，每一步都有保留或复制条件。

`/起重机天钩` 的机制是审查解释有没有跳步。只要解释说“复杂结构来自智能设计者”，就要继续问：这个设计者的复杂性从哪里来？如果解释只把问题后移，它就是天钩。更好的解释要给出可累积中间机制，例如选择、学习、重组、模块化、反馈、局部优化和保留机制。

这张卡不是否认现实中存在工程设计者。它问的是：当一个解释试图说明复杂性来源时，是否给出了能逐步生成复杂性的机制。

## 用户模式

### 触发场景

- 解释需要跨越巨大复杂性差距。
- 有人说某结构“看起来必须有人设计”，但没有解释复杂性如何形成。
- 一个论证引入设计者、神秘本质或一次性跳跃来解释复杂秩序。
- 你需要为一个复杂结构找多个可累积中间机制。

### 操作步骤

1. 写出要解释的复杂性差距。
2. 标出当前解释是否直接跳到成熟结构。
3. 如果引入设计者，追问设计者自身复杂性从何而来。
4. 寻找起重机机制：变异选择、学习反馈、模块复用、局部优化、市场/环境筛选、文化复制等。
5. 为每个起重机写中间阶段。
6. 检查每一步如何被保留、复制或强化。
7. 判断解释是天钩、起重机、部分起重机，还是需要补机制。

### 输出结构

```text
待解释复杂性：
当前解释：
天钩嫌疑：

可能起重机：
1.
2.
3.

中间阶段：
保留/复制机制：
结论：
```

## agent 自救模式

### 卡住信号

- 我用“设计者”“本质”“智能突然出现”跨过了复杂性差距。
- 我没有说明中间阶段如何存在。
- 我引入一个更复杂的解释者，却没有解释它。
- 当前解释听起来完整，但只是把问题后移。

### 自救动作

1. 标出复杂性差距。
2. 圈出天钩词：设计者、本质、神秘跳跃、突然出现。
3. 生成至少三个起重机候选。
4. 为每个候选写保留机制。
5. 选择能减少跳步的解释，标出仍缺的环节。

### 轻量输出

```text
工具：/起重机天钩
当前卡点：解释可能用天钩跨过复杂性差距。
本工具给出的拆分：复杂性差距 / 天钩嫌疑 / 起重机机制 / 中间阶段 / 保留条件。
下一步：找能逐步搭建复杂性的机制。
```

## 误用边界

- 智能设计如果不解释设计者来源，只是把问题后移。
- 不要把“起重机”写成另一个口号。每一步都要有保留或复制条件。
- 不要否认真实工程设计。若有明确设计史，问题可能是责任和实现细节，而不是复杂性来源。
- 不要要求每个起重机一次解释全部复杂性。多个起重机可以叠加。

## 小测试问题

请用 `/起重机天钩` 把一个“看起来必须有人设计”的结构，写出至少三个可能的起重机机制。

## 测试运行结果

待解释复杂性：

一个内容平台的推荐流看起来非常懂用户，总能推送用户愿意继续看的内容。直觉说法是：“这一定是某个天才设计者写出了懂人的规则。”

当前解释：

天才设计者直接写出一套完整规则，准确知道每个用户想看什么。

天钩嫌疑：

高。这个解释没有说明设计者如何知道全部偏好，也没有说明复杂推荐策略如何形成，只把复杂性归给一个更复杂的头脑。

可能起重机：

1. 用户反馈选择：
   系统不断记录点击、停留、跳出、收藏、关注和屏蔽。能提高互动的排序策略被保留，效果差的策略被降权。

2. 局部特征组合：
   从简单特征开始，例如主题、作者、时长、发布时间、相似用户行为。特征逐步组合成更细的偏好画像，而不是一次性理解用户。

3. 模型迭代和 A/B 测试：
   多个模型版本并行测试。表现更好的版本进入主流量，差版本淘汰。每轮只改一部分策略，逐步累积改进。

4. 内容和用户共同适应：
   创作者观察推荐反馈后调整标题、选题和节奏，平台分发机制也随之更新，形成共同演化。

中间阶段：

第一阶段只按热门内容推荐；第二阶段按用户点击主题推荐；第三阶段加入停留和负反馈；第四阶段加入相似用户；第五阶段加入长期兴趣和短期兴趣平衡；第六阶段加入多样性和疲劳控制。

保留/复制机制：

每个阶段如果提高留存、满意度或商业指标，就被保留到下一版本；模型参数、规则、特征和创作者策略都能被复制和迭代。

结论：

“天才设计者直接懂用户”是天钩解释。更好的起重机解释是：用户反馈、特征组合、模型迭代、A/B 测试和内容生态共同逐步搭建出看似聪明的推荐能力。

测试结论：通过。本工具识别了天钩嫌疑，并给出多个可累积、可保留的起重机机制。
