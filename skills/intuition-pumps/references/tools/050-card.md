# 050 噪音利用

## 身份

- 原书标题（中文）：虚拟旅馆的噪音：妙用“意外”是创新的关键
- 英文原名：Noise in the Virtual Hotel
- 中文标题来源：书内译名 + 书内副题。卡片标题“给模型保留可利用的意外”是 skill 化后的功能副题。
- 原书分组：第五部分 关于进化论的思考工具
- 中文短命令：/噪音利用
- 别名：50、工具50、虚拟旅馆的噪音、虚拟旅馆的噪音：给模型保留可利用的意外
- 工具家族：解释生成
- 默认输出重量：中等。输出被省略的副作用、可加入的噪声、选择机制、观察指标和停止条件。
- 对应 issue：ISSUE-059 / TOOL-050

## 名称与思想实验

“虚拟旅馆的噪音”从一个反直觉差异开始：真实旅馆天生有隔壁声音、阴影、气味、震动、污垢、脚印和磨损；虚拟旅馆默认却是寂静的。你不是要费力隔音，而是要费力把声音、碰撞、痕迹和非隔离性写进程序。电脑游戏里的碰撞检测也是同一个问题：屏幕上的物体如果没有额外规则，就会毫无影响地彼此穿过。

丹尼特用这个差异说明计算机模型的一个优势也是限制：虚拟世界可以从一张干净白板开始，只发生建模者明确加入的事；但真实世界中的创造性常常依赖“自发侵入”。现实里的东西会留下痕迹、散布影响、制造偶然交叉，自然选择能够把这些意外噪声转化为信号。卡尔·西姆斯的虚拟生物能进化出游泳、行走、跳跃等策略，但它们的遗传系统仍在模型外部，虚拟碎片的碰撞不能反过来改写基因组或表达规则。

短命令 `/噪音利用` 因此不是要求随便加随机，而是提醒：过度干净的模型会失去可被利用的偶然。使用时要先找出系统删掉了哪些现实副作用，再给它们小剂量入口，同时建立筛选机制。噪声本身不是创新；能被保留、放大、转用的意外，才可能变成功能、线索、作品或意义。

## 原书机制转译

这个工具处理“模型太干净所以没有新东西”的问题。很多模拟、游戏世界、创意流程、研究模型和自动化系统为了可控，会删掉摩擦、延迟、碰撞、副作用、失败痕迹和偶然交叉。这样确实更整齐，但也可能把现实中可被利用的创新材料一起删掉。

`/噪音利用` 的机制是：先找出系统为了简化而省略了哪些副作用，再判断这些副作用能否被选择机制利用。如果能，就有意保留或加入少量噪声、交叉输入、延迟、痕迹、错误传播、局部冲突，让系统产生可筛选的变异。

关键不在“多加随机”，而在“随机之后谁来选择”。没有选择机制的噪声只是混乱；有筛选、保留、复用和放大的噪声，才可能变成新功能、新线索或新创意。

## 用户模式

### 触发场景

- 你在设计模拟、创意系统、游戏世界、研究模型，发现结果太干净、太可控、太像模板。
- 一个流程效率很高，但总是产出同质答案。
- 你怀疑系统把失败、碰撞、延迟、痕迹、边角案例删得太彻底。
- 你想让 agent、写作流程、产品发现或研究流程产生更多可筛选的新线索。

### 操作步骤

1. 写出当前系统目标：它要生成什么、解释什么、优化什么。
2. 列出为了简化而被删掉的现实副作用：噪声、延迟、冲突、误差、失败记录、边界案例、非目标行为、历史痕迹。
3. 判断每类副作用是否可能携带信息：它是否能暴露隐藏约束、带来新组合、制造可比较差异、留下可复用痕迹。
4. 设计低剂量噪声入口：随机交叉输入、失败痕迹保留、延迟反馈、局部碰撞、反常样本、非典型用户路径。
5. 设计选择机制：谁来筛选，按什么标准筛选，怎样保留有用意外，怎样丢弃纯噪声。
6. 设置保护边界：噪声比例、可回滚范围、安全禁区、时间盒、失败上限。
7. 观察是否产生新功能、新假设、新表达、新测试用例或新问题分类。
8. 只保留被选择机制证明有用的意外，不把噪声常态化。

### 输出结构

```text
当前系统：
太干净的表现：

| 被省略的副作用 | 可能携带的信息 | 加入方式 | 选择机制 | 风险控制 |
| --- | --- | --- | --- | --- |
|  |  |  |  |  |

本轮噪声剂量：
保留规则：
丢弃规则：
观察指标：
停止条件：
```

## agent 自救模式

### 卡住信号

- 我不断生成结构正确但没有新意的答案。
- 我把失败样本、边角输入、反常例子都清掉了。
- 我只追求稳定输出，没有给探索留入口。
- 我想加随机性，但没有筛选标准。
- 当前模型缺少现实摩擦，导致结论太平滑。

### 自救动作

1. 标出当前流程被过度清洁的地方。
2. 加入一个小剂量、可回滚的意外源。
3. 明确选择标准：有信息量、可解释、能推动下一步、风险可控。
4. 保留失败痕迹中有价值的一段，而不是保留整个失败。
5. 记录这次噪声是否产生新假设或新选项。

### 轻量输出

```text
工具：/噪音利用
当前卡点：流程太干净，可能把可利用的意外也删掉了。
本工具给出的拆分：省略的副作用 / 小剂量噪声入口 / 选择机制 / 风险边界。
下一步：加入一个可回滚的意外源，并只保留通过筛选的结果。
```

## 误用边界

- 噪声必须能被选择机制利用。纯混乱只会降低效率。
- 不要在安全、合规、生产数据、用户权益或不可回滚环境里随意加噪声。
- 不要把随机输出直接当创意。创意来自变异加筛选，不来自变异本身。
- 不要让噪声吞掉主任务。探索应有剂量、时间盒和停止条件。
- 不要只保留成功结果。失败痕迹可能有用，但要提取可复用信息，而不是堆积垃圾。

## 小测试问题

请用 `/噪音利用` 给一个创意生成流程加入“随机交叉输入”和“保留失败痕迹”两个环节，并判断这些意外噪声是否应被模型利用。

## 测试运行结果

当前系统：

一个用于生成文章选题的创意流程。原流程是：输入主题，列出读者痛点，生成 10 个标题，选择最清晰的 3 个。问题是结果稳定但同质，常常像常规教程。

太干净的表现：

流程只使用主题内材料；失败标题被直接删除；没有跨领域输入；没有记录“为什么失败”；筛选只看清晰度，不看新信息。

| 被省略的副作用 | 可能携带的信息 | 加入方式 | 选择机制 | 风险控制 |
| --- | --- | --- | --- | --- |
| 随机交叉输入 | 带来主题外类比和新角度 | 每轮随机抽 2 条异域材料：一条用户真实抱怨，一条非本领域笔记 | 只保留能改变问题看法、能连接读者痛点的交叉点 | 每轮最多 2 条，不让主题被带偏 |
| 失败标题痕迹 | 暴露无聊、空泛、夸张或难懂的模式 | 每个失败标题不删除，写一句失败原因 | 保留失败原因中可转化的约束，如“太抽象”“缺场景”“承诺过大” | 失败库每轮只保留 3 条约束 |
| 轻微延迟反馈 | 让初稿和二次判断产生距离 | 生成后等待一轮，再用读者视角重看 | 如果二次判断能发现假兴奋，就修正标题 | 不拖成无限打磨 |

本轮噪声剂量：

- 随机交叉输入 2 条：客服抱怨“教程看完还是不知道第一步做什么”；旧笔记“真实系统的摩擦常常暴露隐藏需求”。
- 保留失败痕迹 3 条：标题太像教程、没有第一步、没有现实摩擦。

保留规则：

只保留能让选题更具体、更贴近真实卡点、更能产生新问题分类的意外。

丢弃规则：

只制造炫技类比、偏离主题、增加表达噪音但不改变判断的输入丢弃。

观察指标：

新选题是否多出一个原流程没有的角度；读者是否能看出第一步；失败痕迹是否转化为下一轮约束。

停止条件：

连续两轮随机交叉输入没有改变选题判断，停止加噪声，回到主流程。

利用结果：

原选题：“如何提升写作效率”

加入噪声后得到的新选题：“为什么你看了很多写作教程，还是卡在第一步：把失败标题当成需求探针”

判断：

这次噪声应被利用。随机交叉输入把“写作效率”从泛泛技巧转成“第一步卡点”；失败痕迹把“标题不好”转成可复用约束。噪声被选择机制转化成了更具体的读者问题，不是纯随机装饰。

测试结论：通过。本工具为创意流程加入了随机交叉输入和失败痕迹保留，并通过选择机制判断哪些意外噪声值得利用。
