# 003 拉波波特

## 身份

- 原书标题（中文）：拉波波特法则：批评他人的正确方式
- 英文原名：Rapoport's Rules

- 原书分组：第一部分 通用思考工具
- 中文短命令：/拉波波特
- 别名：03、工具03、拉波波特法则、拉波波特法则：先把对方说到他愿意点头
- 工具家族：论证检验
- 默认输出重量：中等。输出对方认可版摘要、同意点、学到的东西和之后的批评。
- 对应 issue：ISSUE-012 / TOOL-003

## 名称与思想实验

“拉波波特法则”得名于阿纳托尔·拉波波特。丹尼特介绍他时，特别提到他既是社会心理学家、博弈论专家，也是囚徒困境锦标赛中“一报还一报”策略的提出者。这个背景很重要：这套法则不是单纯礼貌，而是一种在冲突中维持合作可能性的策略。

原书把它放在归谬法之后，是因为批评很容易滑向另一种坏习惯：你急着找对方的矛盾，于是把对方观点读成最容易攻击的版本。这样虽然让支持者觉得痛快，却没有真正击中对方的立场。拉波波特法则就是这种嘲讽式批评的解毒剂。

它的核心画面是：在你开口批评之前，先把对方观点重述到对方会希望自己当初也这样表达；再列出你同意的非平凡部分；再说清你从对方那里学到了什么。只有完成这些动作，批评才正式开始。因此这个名字对应的操作不是“说话客气”，而是“先证明自己打中的是真靶，再扣动扳机”。

## 原书机制转译

这个工具解决的是批评中的靶心问题。很多反驳之所以无效，不是因为结论一定错，而是因为它反驳的是一个被削弱、被误读或被情绪化处理的版本。

拉波波特法则要求批评者先做三件反直觉的事：把对方观点重述到对方愿意点头；列出自己承认的合理之处；说明自己从对方那里学到了什么。这样做会迫使批评者理解对方观点真正承担工作的部分，也降低争论双方的防御姿态。

只有完成这些动作后，批评才更可能击中真实立场。

## 用户模式

### 触发场景

- 你要写批评、评审、反驳、评论或回应争议观点。
- 你怀疑自己可能打的是稻草人。
- 对方观点让你不舒服，但其中可能有真实洞见。
- 你希望批评对方强版本，而不是批评弱版本。

### 操作步骤

1. 写出“对方认可版摘要”：目标是让对方说“对，这就是我的意思，甚至比我说得更清楚”。
2. 列出你同意的部分，尤其是那些不流俗但确实有价值的点。
3. 写出你从对方观点里学到的东西，哪怕你最终不同意。
4. 再提出批评，并明确批评只针对哪里。
5. 检查批评是否仍然击中第 1 步的强版本摘要。

### 输出结构

```text
对方认可版摘要：

我同意的部分：
1.
2.

我学到的东西：

我的批评：

批评靶心检查：
这条批评击中的是……
```

## agent 自救模式

### 卡住信号

- 我准备批评，但还没有写出对方会认可的版本。
- 我的反驳主要依赖“不就是……”这种压缩。
- 我只看到了对方最弱表达，没有处理强表达。
- 用户要求评审或反驳，而我可能会直接输出否定意见。

### 自救动作

1. 暂停批评。
2. 先写对方认可版摘要。
3. 列出至少一个同意点或学到的东西。
4. 再提出批评。
5. 如果写不出强版本，先承认还不能批评到位。

### 轻量输出

```text
工具：/拉波波特
当前卡点：我可能还没击中对方真实立场。
本工具给出的改写或检查：先写对方认可版摘要，再批评。
下一步：确认批评是否仍然击中强版本。
```

## 误用边界

- 这不是礼貌开场白。空泛称赞不能替代真实重述。
- 不要为了显得公正而虚构同意点。
- 不适合用来拖延明确判断。理解对方之后仍然可以强烈反对。
- 对恶意操纵、明确违法或高风险欺骗，不必把“善意重述”变成替对方洗白。

## 小测试问题

请用 `/拉波波特` 批评这个观点：“为了效率，77 张工具卡应该用统一模板一次性生成。”

## 测试运行结果

对方认可版摘要：

这个观点真正关心的是效率和一致性。77 张工具卡数量很大，如果完全手工处理，容易耗时、格式不一致、遗漏字段。统一模板一次性生成可以保证每张卡都有相同结构，也能更快进入可测试状态。

我同意的部分：

1. 77 张卡确实需要一致结构，否则后续路由和验证会很难。
2. 基础字段和验收项目需要标准化，否则会变成随意写作。

我学到的东西：

这个观点提醒我：反对批量生成，不等于反对统一验收标准。我们仍然需要模板、索引和验证清单。

我的批评：

问题不在“模板”，而在“一次性生成并视为完成”。本项目的核心风险是每个思考工具从文本到 skill 命令的转译不同。如果一次性生成，最可能丢掉的正是机制差异、误用边界和小测试质量。

批评靶心检查：

这条批评击中的不是“要不要一致结构”，而是“能不能把统一模板生成等同于逐卡转译完成”。因此它没有否定对方关于一致性的合理担忧。

测试结论：通过。本工具先重建了对方关于效率和一致性的强版本，再保留合理部分，最后把批评落在“一次性生成即完成”的关键问题上。
