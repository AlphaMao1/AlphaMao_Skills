## 名称与思想实验

“计算机施展魔法的7个秘密”这一章先把计算机放在“看起来像真正魔法”的位置：它能做出几个世纪前的人会视为神迹的事情，但内部没有神奇组织，只有简单操作的组合。丹尼特选择寄存器机作为思想实验平台：盒子或寄存器里放豆子，处理单元只会结束、增量、减量和遇零跳转，却能组合出加法、移动、复制、减法、乘除和更复杂程序。

“7个秘密”逐步拆掉魔法感：能力可以没有理解；数字的意义由程序决定；数字可表示图案、文本、特征；数字也可表示指令和地址；程序本身可被编码成数据交给通用机执行；后来的机器大多是在速度和架构效率上改进；最后没有额外秘密。看似聪明的计算能力来自表示、条件分支、子程序复用、程序作为数据和速度规模。

因此短命令叫“笨步骤”。它不是贬低计算机，而是提醒使用者：当一个系统看起来智能时，先尝试把它还原为一组不理解自身含义的可组合步骤。只要这些步骤、表示和分支能解释能力，就不需要预设神秘理解者。

## 原书机制转译

这个工具把看似神奇的计算能力拆成可组合的笨步骤。复杂计算不需要每个部件都理解问题；它可以来自基本操作、条件分支、状态存储、表示约定、程序作为数据、通用机结构、可复用子程序和速度/规模优势。

`/笨步骤` 的机制是把“系统很智能”改写成“这个系统接收什么输入，把什么当作状态，用什么符号表示什么，通过哪些分支改变路径，调用哪些子程序，最后输出什么”。如果能力提升主要来自规模和速度，也要和原理变化分开。

这张卡不是说大脑就是普通电脑，也不是说所有智能都只是传统程序。它提供的是一个想象模型：复杂能力可以由无理解步骤组合出来，因此不要过早诉诸神秘理解者。

## 用户模式

### 触发场景

- 你面对一个看似神奇的计算系统、AI 能力或自动化流程，想理解它如何可能。
- 解释里出现“系统自己懂了”“模型突然会了”这种跳步。
- 你要把智能功能拆成输入、状态、条件分支和输出。
- 你要区分能力提升来自新原理，还是来自速度、规模、数据和组合。

### 操作步骤

1. 写出要解释的智能功能。
2. 确定输入：系统接收哪些数据或信号。
3. 确定表示：数字、符号、向量、标签或结构分别代表什么。
4. 确定状态：系统记住了什么，中间变量存在哪里。
5. 确定条件分支：哪些条件会让流程走不同路径。
6. 找出可复用子程序：排序、匹配、搜索、评分、过滤、更新、压缩等。
7. 检查程序是否被当成数据处理：配置、规则、模型权重、提示词、脚本、代码生成。
8. 区分能力来源：原理变化、组合方式、速度提升、规模扩大、训练数据、反馈循环。
9. 输出一个无需理解部件也能运行的机制草图。

## agent 自救模式

### 卡住信号

- 我说系统“理解/判断/推理”，但没有拆出输入、状态、分支和输出。
- 我把 AI 能力写得像魔法，没有说明可组合步骤。
- 我把速度、规模和原理变化混在一起。
- 当前解释不能让用户想象系统怎样一步步运行。

### 自救动作

1. 把智能功能压成一个输入到输出的任务。
2. 写表示和状态。
3. 写条件分支和可复用子程序。
4. 标出是否有程序作为数据的环节。
5. 判断能力提升来自组合、速度、规模还是新机制。

### 轻量输出

```text
工具：/笨步骤
当前卡点：我可能把计算能力写成了魔法。
本工具给出的拆分：输入 / 表示 / 状态 / 条件分支 / 子程序 / 程序作为数据 / 速度规模。
下一步：把聪明输出还原成无理解步骤的组合。
```

## 误用边界

- 这不是说大脑就是普通电脑，而是提供“复杂能力可由无理解步骤组成”的可想象模型。
- 不要用笨步骤否认高层模式。高层能力可以真实存在，只是由低层步骤实现。
- 不要把所有社会、法律、伦理或价值问题都计算化。这个工具只解释计算机制可行性。
- 不要只列流程图。必须说明表示、状态和分支，否则仍然像魔法。

## 小测试问题

请用 `/笨步骤` 把一个“智能邮件垃圾分类”功能拆成寄存器机视角：输入是什么、状态是什么、条件分支是什么、输出是什么。

## 测试运行结果

智能功能：

自动判断一封邮件是否为垃圾邮件。

| 检查口 | 当前系统里的对应物 |
| --- | --- |
| 输入 | 邮件标题、正文、发件人、链接、附件、历史互动、用户标记记录 |
| 表示 | 文本被表示为词、短语、字符模式、向量、链接特征、发件人信誉分、时间特征 |
| 状态 | 模型权重、黑白名单、用户偏好、历史分类结果、阈值、临时评分 |
| 条件分支 | 如果发件人在白名单则降低垃圾分；如果包含高风险链接则提高垃圾分；如果总分超过阈值则进入垃圾箱 |
| 子程序 | 分词、特征提取、链接检测、信誉查询、相似度匹配、评分、阈值判断、用户反馈更新 |
| 程序作为数据 | 模型权重、规则配置、黑白名单和阈值都可以被读取、更新和版本化 |
| 速度/规模 | 系统能在极短时间内比较大量历史邮件和规则，人手无法逐封完成同等规模检查 |

机制草图：

邮件进入系统后先被解析为多个特征；特征被转换成可计算表示；模型和规则对子特征打分；多个分数被合成总风险；条件分支根据阈值决定收件箱、垃圾箱或待确认；用户后续标记会更新偏好或训练数据。

能力来源：

主要来自表示约定、统计/规则组合、历史数据、可复用检测子程序、用户反馈和速度规模。系统不需要像人一样理解“诈骗意图”，也能通过特征组合有效识别许多垃圾邮件。

仍未解释部分：

具体模型如何学习权重、如何处理新型诈骗邮件、如何避免误杀重要邮件，还需要更细训练和评估机制。

测试结论：通过。本工具把一个看似智能的分类功能拆成输入、表示、状态、条件分支、子程序、程序数据化和速度规模，没有诉诸神秘理解。
