# 026 算法

## 身份

- 原书标题（中文）：算法：有效解决问题的策略机制
- 英文原名：Algorithms
- 中文标题来源：书内译名 + 书内副题。卡片标题“把方法写成无需理解也能执行的步骤”是 skill 化后的功能副题。
- 原书分组：第三部分 关于计算机的思考工具
- 中文短命令：/算法
- 别名：26、工具26、算法、算法：把方法写成无需理解也能执行的步骤
- 工具家族：解释生成
- 默认输出重量：中等。输出输入、步骤、分支、停止条件、输出、手动跑样例和含糊词清单。
- 对应 issue：ISSUE-035 / TOOL-026

## 名称与思想实验

“算法”这一章把达尔文、计算机和日常算术放在同一个画面里看：长除法、结算账簿、井字棋的完美走法、单词排序、计算机程序，以及自然选择，都可以被理解为某种只要运行起来就会产生特定结果的形式步骤。丹尼特强调，达尔文的重要性不只是提出了一个生物学故事，而是让我们看见算法可以在没有聪明设计者逐步干预的情况下，长期地产生复杂秩序。

原书给算法列出三项核心特征。第一是底层中立：同一个长除法过程可以用铅笔、钢笔、霓虹灯或别的符号载体执行，材料影响速度和可靠性，但不决定算法的逻辑结构。第二是潜在无头脑：每个局部步骤简单到不需要理解深层意义，像极度详细的新手菜谱。第三是结果有保障：只要输入、条件和执行不出错，过程会按同一机制反复得到同类结果。

因此 `/算法` 不是把“算法”当成现代软件黑箱，而是把一个方法压成可以被低理解执行者运行的步骤。使用者要问：输入是什么，下一步由什么条件决定，什么时候停，输出是什么；如果某一步还需要“看感觉”“判断好坏”，它就还没有真正算法化，或者必须显式保留人工判断。

## 原书机制转译

这个工具把“方法”改写成算法。算法是一组明确、有限、可重复的步骤：执行者不需要理解深层意义，只要能按步骤操作，就能在合适输入上得到预期输出。它适合把模糊经验、教学流程、筛选流程、诊断流程和 agent 操作规程变得可复用。

`/算法` 的机制不是把所有事情都机械化，而是检查一个方法中哪些部分能被明确化：输入是什么，每一步做什么，遇到不同情况如何分支，什么时候停止，输出什么，用简单样例跑一遍是否能执行。不能算法化的部分也要圈出来，避免伪精确。

这张卡尤其适合把“凭感觉做”的流程变成 skill、清单、SOP 或测试步骤。

## 用户模式

### 触发场景

- 你要判断一个问题能否程序化、流程化、教学化。
- 你想把模糊方法变成可复用步骤。
- 你正在写 skill、SOP、检查表、评分规则或自动化流程。
- 你怀疑当前流程里有太多“看情况”“合适”“好文章”等含糊词。

### 操作步骤

1. 定义输入：执行者拿到什么材料。
2. 定义输出：执行完成后必须交付什么。
3. 写出每一步操作，用动词开头，避免抽象判断。
4. 为关键分叉写条件：如果 A，则做 B；否则做 C。
5. 写停止条件：什么时候算完成，什么时候必须暂停或升级。
6. 用一个简单样例手动跑一遍。
7. 圈出仍然含糊的词，并决定补定义、保留人工判断，还是标为不可算法化部分。

### 输出结构

```text
目标方法：
输入：
输出：

算法步骤：
1.
2.

分支条件：
停止条件：
手动跑样例：
含糊词/不可算法化部分：
结论：可算法化 / 部分算法化 / 不适合算法化
```

## agent 自救模式

### 卡住信号

- 我写了建议，但用户无法照着做。
- 我把“判断好坏”“选择合适方案”留给执行者猜。
- 我想自动化一个流程，但没有定义输入、输出和停止条件。
- 我不断重复解释原则，却没有形成可执行步骤。

### 自救动作

1. 把方法改写成输入到输出的流程。
2. 每一步用可执行动词。
3. 写分支和停止条件。
4. 用小样例手跑。
5. 标出不能算法化的判断并保留人工口。

### 轻量输出

```text
工具：/算法
当前卡点：方法还停在原则层，执行者不知道具体怎么做。
本工具给出的拆分：输入 / 步骤 / 分支 / 停止条件 / 输出 / 手跑样例 / 含糊词。
下一步：把可明确部分算法化，把不可算法化部分显式保留。
```

## 误用边界

- 不是所有问题都适合完全算法化。审美、开放探索和价值判断通常只能部分算法化。
- 不要把含糊词藏进步骤里。好、合适、重要、优质、相关都需要标准。
- 不要用流程假装解决价值判断。算法可以整理证据，但阈值和取舍可能仍需人定。
- 不要为了可执行而删掉关键背景。步骤简单不等于问题简单。

## 小测试问题

请用 `/算法` 把“筛选好文章”写成算法，再圈出仍然不能算法化的判断。

## 测试运行结果

目标方法：

筛选好文章。

输入：

一批候选文章，每篇至少包含标题、正文、作者、发布时间、来源链接。

输出：

入选文章清单，每篇附上入选理由、风险标记和人工复核项。

算法步骤：

1. 删除无法打开、正文缺失或重复的文章。
2. 为每篇文章提取主题、核心主张、证据类型和目标读者。
3. 检查文章是否有明确问题或主张；没有则标为低优先级。
4. 检查证据：是否引用数据、案例、一手材料、可追溯来源或清晰推理。
5. 检查信息增量：与常见观点相比，是否提供新事实、新框架、新案例或新问题。
6. 检查结构：标题、开头、论证、例子和结论是否能形成连续阅读路径。
7. 检查风险：是否有明显事实错误、夸张标题、无法验证断言、广告软文或情绪操纵。
8. 根据评分表排序：主张清晰度、证据强度、信息增量、结构完整度、风险程度各 0-3 分。
9. 选择总分高且风险低的文章进入候选清单。
10. 对候选清单做人工复核，确认它是否符合当前读者和使用场景。

分支条件：

- 如果文章缺正文或重复，则剔除。
- 如果证据强度低于 1 分但主张很强，则标记为高风险。
- 如果信息增量高但结构差，则保留为“素材”，不作为直接推荐文章。
- 如果总分高但含商业利益冲突，则进入人工复核。

停止条件：

候选文章数量达到目标数量，且每篇都有入选理由和风险标记；或者所有文章都被处理完。

手动跑样例：

文章 A：标题清楚，提出“某技术路线成本下降”的主张，引用企业财报和专利数据，有案例，有边界说明。主张清晰 3，证据强度 3，信息增量 2，结构 2，风险 1，可入选。

文章 B：标题是“震惊，行业要变天”，正文只有情绪判断，没有来源。主张清晰 1，证据 0，信息增量 0，风险 3，剔除或只作舆情样本。

含糊词/不可算法化部分：

“好文章”仍依赖读者目标、审美偏好、当前议题价值和使用场景。算法可以筛掉明显差文章，并提出高质量候选，但最后是否“值得读”需要人根据目的判断。

结论：

部分算法化。去重、证据检查、结构检查和风险标记可以流程化；最终价值判断和审美判断需要保留人工复核。

测试结论：通过。本工具把“筛选好文章”拆成可执行流程，并明确标出仍需人工判断的部分。
