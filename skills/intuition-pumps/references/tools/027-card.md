## 名称与思想实验

“让电梯实现自动控制”是丹尼特为规则遵循问题设计的玩具问题。原书先让读者想象早期电梯操作员：他们接受训练，记住什么时候上升、下降、停靠、开门、提醒乘客，并把这些规则练成第二天性。然后设定一个制造商把操作手册交给程序员，要求他们写一个程序，让芯片取代优秀操作员。

这个思想实验的关键不是电梯本身，而是规则在不同层级上的变形。操作手册是人类可读规则；程序员先写伪代码，再写更严格的源代码；注释帮助人类理解源代码意图；编译器把源代码转为目标代码；目标代码烧进芯片后，通过传感器输入和电机、显示器、录音等执行器输出，产生看似遵守同一套规则的行为。

丹尼特随后提醒：自动电梯并不等于在内部逐句保存和理解那本操作手册。它在行为上近似替代了人类操作员，但内部可能只是传感器条件、控制状态和目标代码。短命令 `/电梯控制` 因此要求使用者把“遵守规则”拆开：规则文本在哪里，编译或训练后的实现在哪里，行为等价范围在哪里，哪些结论不能从合规输出直接推出。

## 原书机制转译

这个工具处理“系统遵守规则”这句话的歧义。一个系统的行为可以像是在遵守人类可读规则，但这不代表系统内部保存着同样的规则句子，更不代表系统理解这些句子。规则可以被写成源代码、被编译成目标代码、被实现成硬件电路、被训练成习惯，最后只在行为上近似等价。

`/电梯控制` 的机制是把规则从文本层拆到实现层：人类操作员会说什么规则，自动系统有哪些传感器、条件分支和执行器，源代码/注释/目标代码/硬件之间有什么差异，最终行为在哪些情境下等价，在哪些边界下不等价。

它适合解释 AI、自动化系统、习惯、组织流程、动物行为和人类技能中的“规则遵循”问题。

## 用户模式

### 触发场景

- 你要解释一个系统“遵守规则”，但不确定规则是否真的以文字形式存在于系统内部。
- 你需要区分人类可读规则、源代码、注释、目标代码、硬件反应和训练出的行为。
- 你在分析系统输出合规，但不能确定它是否理解规则。
- 你要比较人类操作员规则版和自动系统传感器版。

### 操作步骤

1. 写出人类可读的显性规则。
2. 写出系统实际接收的传感器或输入信号。
3. 写出系统内部条件分支或控制逻辑。
4. 写出执行器或输出动作。
5. 区分源规则、源代码、注释、目标代码、硬件反应和训练参数。
6. 比较行为等价：在哪些输入下行为和规则一致。
7. 比较内部差异：系统是否保存规则文本、是否能解释规则、是否只是行为近似。
8. 给出结论：文本规则、编译规则、习惯化规则、行为近似，或真正规则理解。

## agent 自救模式

### 卡住信号

- 我因为系统输出合规，就写它理解或遵守了规则。
- 我把规则文本和系统内部表示混为一谈。
- 我没有区分注释、源码、编译结果和运行时行为。
- 当前解释无法说明系统在边界情境下会不会继续合规。

### 自救动作

1. 抽出人类可读规则。
2. 写系统实际输入、分支和输出。
3. 标出规则在内部是文本、代码、参数、硬件，还是只表现为行为。
4. 写行为等价范围和失效边界。
5. 把“理解规则”降级为更精确表述。

### 轻量输出

```text
工具：/电梯控制
当前卡点：我可能把合规行为当成规则理解。
本工具给出的拆分：规则文本 / 输入传感器 / 条件分支 / 执行器 / 内部表示 / 行为等价。
下一步：说明规则被如何实现，而不是假设系统保存同一句规则。
```

## 误用边界

- 不要因为输出合规，就断言系统理解了规则。
- 不要把“内部没有规则文本”误解成“没有规则性”。行为仍可能被控制逻辑稳定约束。
- 不要忽略注释和源码的区别。注释给人看，编译结果才直接驱动机器。
- 不要把所有规则遵循都降级成机械反应。人类也可能显式理解规则，但要看证据。

## 小测试问题

请用 `/电梯控制` 拿“电梯到楼层开门”写出人类规则版和机器传感器版。

## 测试运行结果

人类规则：

当电梯到达目标楼层并停稳后，打开电梯门；如果门口有障碍物，不要关门。

| 层级 | 内容 |
| --- | --- |
| 人类可读规则 | 到目标楼层、停稳、开门；有障碍时保持门开 |
| 输入/传感器 | 楼层位置传感器、速度/停稳信号、门区位置开关、门缝红外或压力传感器、按钮输入 |
| 条件分支 | 如果当前位置等于目标楼层且速度为 0 且在门区，则触发开门；如果障碍传感器被触发，则停止关门或重新开门 |
| 执行器/输出 | 门电机启动、制动器状态、楼层显示、提示音 |
| 内部表示 | 可能是控制器状态、布尔变量、PLC 梯形图、目标代码或电路状态，不一定有“到楼层就开门”这句话 |

行为等价范围：

在正常传感器工作、楼层信号准确、门区检测可靠的情况下，机器行为等价于人类规则：到目标楼层停稳后开门，有障碍时不开门。

内部表示差异：

人类操作员可以理解“楼层”“停稳”“安全”的意义，并在异常情况下解释原因。自动电梯可能只执行传感器条件和控制逻辑；它未必保存规则文本，也未必理解安全概念。

不能推出的结论：

不能因为电梯正确开门，就说它理解了“安全规则”。也不能因为它没有规则文本，就说它没有规则性。更准确是：规则被编译或实现为传感器条件、控制状态和执行器动作。

结论：

“电梯遵守开门规则”在行为层成立；在内部表示层，它更像编译后的控制逻辑，而不是保存并理解人类可读规则文本。

测试结论：通过。本工具区分了人类规则版和机器传感器版，避免把行为合规直接等同于规则理解。
