# 017 常识心理

## 身份

- 原书标题（中文）：常识心理：人们无需正规教育就拥有的一种能力
- 英文原名：Folk Psychology
- 中文标题来源：书内译名 + 自拟功能副题。卡片标题“把行动者看成有信念和欲望”是 skill 化后的操作性改写。
- 原书分组：第二部分 关于意义和内容的思考工具
- 中文短命令：/常识心理
- 别名：17、工具17、常识心理、常识心理：把行动者看成有信念和欲望
- 工具家族：视角切换
- 默认输出重量：中等。输出信念-欲望解释、行为预测、替代解释和校正条件。
- 对应 issue：ISSUE-026 / TOOL-017

## 名称与思想实验

“常识心理”指的是普通人无需正规心理学训练就会使用的一套解释能力：我们会把周围的人、动物、机器人，甚至某些简单装置，看成拥有信念、欲望、目标和选择的行动者。丹尼特更喜欢这个中性名字，而不喜欢把它叫作“心智理论”，因为后者容易让人误以为我们是在显式套用一套理论。

原书用几个画面说明这种能力有多自然。迎面驶来的车辆不会让你立刻恐慌，因为你默认对方也想活下来，也会按路规行动。海德-西梅尔动画里，几何图形只是进出一个框，我们却很难不把它们看成在追逐、躲避、威胁或合作。这个反应非常强大，也可能过度触发。

所以这张卡的名字对应的操作是：允许使用信念-欲望解释，但把它降格为可校正的工作假设。它能快速预测行为，但不能自动证明对象真的拥有完整心智；如果预测失败，或机制解释更简单，就要把心理故事降级。

## 原书机制转译

这个工具把常识心理学变成可检查的行为解释方法。人类天然会用“他相信什么”“他想要什么”“他害怕什么”“他打算什么”来解释行为。这种解释在日常互动中非常高效，可以快速预测下一步，但它也容易把无心智系统、简单反射、设计机制或随机波动误读成完整意图。

`/常识心理` 的机制是先允许你使用信念和欲望模型，再要求你把它变成可被行为校正的假设。它不是说每个被解释对象真的有完整心智，而是说在某些任务中，用“信念-欲望-行动”框架能产生有用预测。

这张卡和 `/意向立场` 相邻，但焦点不同：`/常识心理` 更偏日常解释和过度拟人化检查；`/意向立场` 更偏把系统暂时当作理性行动者来预测复杂系统行为。

## 用户模式

### 触发场景

- 你要预测人、动物、组织、软件代理、产品用户或虚构角色的行为。
- 你想解释一个行为，但只有外部观察，没有内部状态证据。
- 你怀疑自己把系统过度拟人化了。
- 你需要比较常识心理解释、机制解释和随机解释。

### 操作步骤

1. 写出被解释的具体行为，不先写动机。
2. 写常识心理解释：行动者可能相信什么、想要什么、害怕什么。
3. 从这个解释推出下一步可观察预测。
4. 写至少两个替代解释：设计/机制解释、物理/环境约束解释、随机/误触解释。
5. 用实际行为或新证据比较这些解释。
6. 如果常识心理预测失败，降级或切换到设计立场、物理立场或随机解释。
7. 结论只写到证据允许的强度：像是、有理由推测、暂不支持、应改用机制解释。

### 输出结构

```text
待解释行为：

常识心理解释：
- 可能信念：
- 可能欲望/目标：
- 预测下一步：

替代解释：
- 机制/设计：
- 环境/物理：
- 随机/噪声：

证据比较：
当前最佳解释：
下一步验证：
```

## agent 自救模式

### 卡住信号

- 我说“系统想要”“模型认为”“组织害怕”，但没有把它当假设。
- 我把看起来有目的的行为直接当成心智证据。
- 我只写心理动机，没有写设计机制、环境约束或随机解释。
- 当前预测失败了，我还在加更复杂的心理故事。

### 自救动作

1. 把心理动词改写成假设，而不是事实。
2. 写出该假设会预测什么下一步行为。
3. 写机制解释和随机解释。
4. 用证据比较三种解释。
5. 若心理解释没有增量，改用更低层解释。

### 轻量输出

```text
工具：/常识心理
当前卡点：我可能在把行为过度拟人化。
本工具给出的拆分：信念-欲望假设 / 行为预测 / 机制解释 / 随机解释。
下一步：用新证据校正，而不是继续编动机。
```

## 误用边界

- 看起来有目的，不等于真有完整心智。
- 常识心理解释有预测价值，但不能自动替代机制分析。
- 不要把心理动词写成已确认事实，除非有足够行为、报告或背景证据。
- 不要为了避免拟人化而禁用心理解释。对人和许多组织行为，它仍是高效工作模型。

## 小测试问题

请用 `/常识心理` 解释一个产品用户反复点击“提交”按钮的行为，并分别给出常识心理解释、机制解释和随机解释。

## 测试运行结果

待解释行为：

用户在表单页面 10 秒内连续点击了 6 次“提交”按钮。

常识心理解释：

- 可能信念：用户以为第一次点击没有成功，或者不知道系统正在处理。
- 可能欲望/目标：用户想尽快完成提交，避免内容丢失。
- 预测下一步：如果页面给出明确加载状态或成功反馈，用户会停止重复点击；如果没有反馈，用户可能继续点击或刷新页面。

替代解释：

- 机制/设计：按钮没有禁用状态，提交后没有加载指示，网络延迟导致反馈迟到。
- 环境/物理：鼠标或触控板抖动，移动端触摸误触，设备卡顿。
- 随机/噪声：用户手滑、多点触控误判，或埋点重复记录。

证据比较：

如果日志显示每次点击之间间隔接近 1-2 秒，且页面没有 loading 状态，常识心理解释和设计机制解释共同成立：用户可能在不确定反馈下重复尝试。如果点击间隔毫秒级，随机/设备解释更强。如果按钮在第一次点击后已禁用但日志仍重复，可能是埋点问题。

当前最佳解释：

暂定为“缺少反馈导致用户以为没提交成功”，但这不是用户内心事实，而是可用来改进产品的信念-欲望假设。

下一步验证：

给按钮增加禁用状态、loading 和成功提示，再看重复点击率是否下降。

测试结论：通过。本工具生成了可预测的常识心理解释，同时保留机制和随机替代解释，避免把用户行为直接写成确定动机。
