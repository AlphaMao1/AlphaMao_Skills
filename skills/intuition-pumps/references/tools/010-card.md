# 010 小心当然

## 身份

- 原书标题（中文）：小心“当然”这个词：一种让你无需思考就认同的花招
- 英文原名：The "Surely" Operator: A Mental Block
- 中文标题来源：书内译名 + 自拟功能副题。短命令“小心当然”和卡片标题“把显然性降回待证明命题”是 skill 化后的操作性改写。
- 原书分组：第一部分 通用思考工具
- 中文短命令：/小心当然
- 别名：10、工具10、小心当然、小心“当然”：把显然性降回待证明命题
- 工具家族：论证检验
- 默认输出重量：轻到中等。输出“当然警报清单”、待证明命题、所需证据和薄弱点。
- 对应 issue：ISSUE-019 / TOOL-010

## 名称与思想实验

这张工具的英文名是 “Surely Operator”。`surely` 在中文译本里对应“当然”“显然”一类词。丹尼特把它叫作 operator，是因为它像一个小小的语言操作符：放在句子前面，就能让一个其实需要论证的前提看起来已经获得许可，读者也更容易跟着滑过去。

原书建议在论证性文章里搜索这类词，把它们当作闪烁警灯。原因不是这些词总是错，而是作者通常在这里站在自己把握的边缘：他相信读者也会同意，于是选择直接断言，而不是停下来证明。恰恰在这种地方，最容易藏着未经检验的“自明之理”。

副标题里的 `Mental Block` 也带一点双关。丹尼特用 Ned Block 的意识论文章作例子，指出某些关键处的“当然”会把争议前提包装成生物学常识。作为 skill 命令，这张卡的动作就是拆掉这个操作符：删去“当然”，把后面的句子还原成普通、可争议、需要证据的命题。

## 原书机制转译

这个工具解决的是显然性偷渡问题。论证中的“当然、显然、不言而喻、众所周知”常常让读者跳过检查，把一个有争议、需要证据或需要限定的前提当成常识。

`/小心当然` 的操作不是禁止这些词，而是检查它们后面的句子是否承担了关键论证重量。如果承担了，就把语气词删掉，把句子改写成可争议命题，然后要求证据、理由或例外处理。

## 用户模式

### 触发场景

- 文本中出现“当然、显然、不言而喻、众所周知”等词。
- 这些词后面的句子承担关键论证重量。
- 你觉得某个判断被包装成常识，但其实没有证明。
- 你需要审查自己的文章有没有偷渡前提。

### 操作步骤

1. 搜索文本里的显然性词：当然、显然、不言而喻、众所周知、很明显、无需说明。
2. 把这些词后面的句子单独摘出来。
3. 删除语气词，改写成一个可争议命题。
4. 问：这个命题需要什么证据、理由或例外处理？
5. 如果没有支撑，把它标为论证薄弱点。
6. 如果它只是普通过渡，不承担证明重量，可以放过。

### 输出结构

```text
当然警报清单：
1. 作者说当然的是：
   改写成可争议命题：
   需要的证据：
   当前状态：有支撑 / 无支撑 / 只是过渡
```

## agent 自救模式

### 卡住信号

- 我在输出中用了“显然、当然、很明显”，但没有给证据。
- 我把用户可能不同意的前提当作常识。
- 我在关键步骤靠语气推进，而不是靠理由推进。
- 用户要求审查论证薄弱点。

### 自救动作

1. 搜索自己刚写的显然性词。
2. 抽出后面的句子。
3. 删除语气词，改成待证明命题。
4. 补证据、加限定，或标为薄弱点。

### 轻量输出

```text
工具：/小心当然
当前卡点：有争议前提可能被包装成显然常识。
本工具给出的改写或检查：删掉“当然”，把句子还原成待证明命题。
下一步：补证据、加限定，或标出薄弱点。
```

## 误用边界

- 不是所有“当然”都有问题。它只有在替代证据或遮蔽争议时才危险。
- 不要把这个工具变成逐字洁癖。目标是检查论证重量，不是禁词。
- 如果后文已经提供充分证据，“当然”可能只是语气问题。
- 不要只检查别人，也要检查自己的显然性偷渡。

## 小测试问题

请用 `/小心当然` 检查这句话：“当然，既然有 77 个工具卡，最高效的办法就是先一次性生成完整版本。”

## 测试运行结果

当然警报清单：

1. 作者说当然的是：

既然有 77 个工具卡，最高效的办法就是先一次性生成完整版本。

改写成可争议命题：

对于 77 个工具卡，先一次性生成完整版本是最高效且合适的实现路径。

需要的证据：

- 一次性生成是否能保留每个工具的机制差异。
- 一次性生成是否能通过逐卡小测试。
- “最高效”是否只计算生成速度，而忽略返工、误用和质量审查成本。
- 用户是否接受这种实现方式。

当前状态：

无支撑。该句把“生成速度快”偷换成“整体最合适”，并跳过了质量和用户约束。

修正：

可以改成：一次性生成在速度上可能更快，但本项目的关键约束是逐卡理解和验收，因此不能把生成速度直接当作实现路径的充分理由。

测试结论：通过。本工具把“当然”后面的句子还原成待证明命题，并指出它需要的证据和当前缺口。
