# 008 跳出系统

## 身份

- 英文原名：Jootsing

- 原书分组：第一部分 通用思考工具
- 中文短命令：/跳出系统
- 别名：08、工具08、跳出系统、跳出系统：找出默认不可动的规则
- 工具家族：视角切换

- 对应 issue：ISSUE-017 / TOOL-008

## 名称与思想实验

“Jootsing”来自侯世达使用的说法，意思是 jumping out of the system，也就是跳出系统。这个名字听起来像创造力口号，但丹尼特强调它并不是“随便违反规则”。真正困难的是：先看见自己身处哪个系统，再判断哪些规则真的可以被打破，而且打破之后仍然有意义。

原书用艺术和科学两类场景说明这一点。音乐、诗歌、艺术传统都有格律、风格和预期；如果完全没有规则，随机按琴键只会得到噪音，不会得到创造。科学和哲学也一样，长期争论往往卡在双方共同默认、以为空气一样自然的前提上。跳出系统的关键不是否定所有前提，而是发现那个大家都没再检查的前提。

因此“跳出系统”对应的操作是：先描述系统，列出它的显性规则和隐性假设，再区分硬限制与可动规则。只有当某条规则并非物理、法律或证据约束，而只是习惯、术语、传统或早年的临时假设时，才值得尝试移除、反转或重命名。

## 原书机制转译

这个工具解决的是框架困局：你以为自己在寻找方案，其实只是在一个默认系统内部做小修小补。很多“不能动”的东西并不是物理限制，而是习惯、制度、成本结构、术语边界、审美惯性或叙事设定。

“跳出系统”的机制不是随机反叛，而是把默认规则显性化，并逐条判断它们到底属于哪类限制。只有当你看见某条规则并非硬约束，才有可能通过移除、反转或重命名产生新解释和新方案。

## 用户模式

### 触发场景

- 所有方案都像小修小补。
- 问题被某个默认框架锁住。
- 你听到“这个肯定不能动”，但没人说明为什么。
- 你需要找出哪些约束是真限制，哪些只是默认设置。

### 操作步骤

1. 列出当前系统里大家默认不可动的规则。
2. 给每条规则标注类型：物理限制、法律限制、成本限制、习惯限制、制度限制、术语限制、叙事限制、审美惯性。
3. 对每条非硬限制提问：如果去掉、反转、替换或重命名，会怎样？
4. 保留能产生新解释或新设计的变化。
5. 再把候选变化带回现实约束，筛掉不可行方案。

### 输出结构

```text
默认规则：

规则类型：

反转 / 移除测试：

产生的新可能：

现实筛选：
保留 / 放弃 / 待验证
```

## agent 自救模式

### 卡住信号

- 我给出的方案都只是局部优化。
- 我把某个约束当成事实，却没有说明它的类型。
- 用户问“有没有完全不同的思路”，而我仍在原框架内搜索。
- 我在术语、流程或组织边界里打转。

### 自救动作

1. 写出当前系统默认不可动的 3-5 条规则。
2. 给每条规则标注限制类型。
3. 只挑非硬限制做反转测试。
4. 输出一个新可能和一个现实筛选。
5. 如果全是硬限制，停止幻想，回到约束内优化。

### 轻量输出

```text
工具：/跳出系统
当前卡点：我可能被默认规则锁在系统内部。
本工具给出的改写或检查：列出不可动规则，区分硬限制和软限制。
下一步：反转一个软限制，再做现实筛选。
```

## 误用边界

- 跳出系统不是随机叛逆。移除规则后仍要接受证据和后果检验。
- 不要把法律、安全、物理、预算等硬限制当成“思维枷锁”随便删除。
- 不要沉迷反转本身。反转必须产生可解释、可设计或可验证的新可能。
- 如果问题只是执行不到位，跳出系统可能会逃避基本改进。

## 小测试问题

请用 `/跳出系统` 处理这个卡点：“做这个 skill 时，默认好像必须一次性把 77 个工具卡全部做完，否则就不算实现。”

## 测试运行结果

默认规则：

1. 必须一次性把 77 个工具卡全部做完。
2. 工具卡数量完整才代表 skill 可以推进。
3. 只有最终成品才值得验收。

规则类型：

1. “一次性做完”不是物理限制，也不是格式要求，而是工作流惯性。
2. “数量完整才算推进”是验收叙事，不是技术限制。
3. “最终成品才验收”是项目管理习惯，不是必要规则。

反转 / 移除测试：

如果改成“一次只完成一个工具卡 issue，并记录验收结果”，会怎样？

产生的新可能：

可以在每张卡上真正做机制转译和小测试，避免 77 张卡被批量套模板。skill 不是一次性完成，而是可审计地逐步完成。

现实筛选：

保留。它符合用户明确约束，也降低批量处理风险。代价是总耗时更长，但质量和可追踪性更好。

测试结论：通过。本工具把“必须一次性做完”的默认规则识别为工作流惯性，并通过反转测试产生了更符合当前项目目标的路径。
