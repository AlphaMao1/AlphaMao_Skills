- 对应 issue：ISSUE-085 / TOOL-076

## 名称与思想实验

“像棋”是丹尼特临时发明的国际象棋变体：它几乎像 chess，只是规则改了一点，例如王一次可以走两格。只要规则给定，“像棋”也会立刻产生无穷多先验真理、难题、证明、反证明和二阶争论。一个人完全可以花多年研究“像棋”里的某个定理，甚至再研究别人对这个定理的证明哪里出错。

丹尼特用这个怪词提醒哲学家：哲学确实常常像研究国际象棋一样，在给定规则和概念前提后推导出结论。但不是每套规则系统都像国际象棋一样值得投入。一个问题可以很难、很聪明、很严密、很可发表，却仍然只是“像棋”的二阶真理：规则内成立，外部意义很弱。

短命令 `/问题值不值` 对应赫布那句警告：如果一件事本身不值得做，也就不值得把它做得很漂亮。使用时不是问“我能不能解开这个难题”，而是先问“这个难题连接了什么真实困惑”。外行或聪明本科生是否能听出问题的意义，只是预警信号，不是最终裁判；有些深奥问题仍然值得做，但它们需要更强的重要性证明。

## 原书机制转译

这个工具处理“一个问题极难、极精巧、可无限研究，所以它值得研究”的诱惑。规则系统可以产生无限多真理，就像某种棋类或形式系统里可以有无穷多定理、谜题和二阶性质。但真理很多，不代表每个都值得花生命时间。

`/问题值不值` 的机制是先审查问题重要性，再决定是否投入。它要求你说明这个问题连接什么真实困惑，是否影响科学解释、伦理判断、概念清理、实践决策、工具设计或读者理解。难度、聪明程度、没人做过、同行觉得精巧，都不是重要性的充分条件。

这个工具不是反智，也不是否定纯研究。它只是要求：如果你要投入稀缺注意力，先给出重要性证明。

## 用户模式

### 触发场景

- 你遇到一个极难、极精巧、可无限研究的抽象问题。
- 一个研究题目很新、很难、很像没人做过，但不清楚重要性。
- 你担心自己在自造规则系统里解谜。
- 你需要决定退出、降级、暂存，还是投入。

### 操作步骤

1. 写出研究问题，不超过两句话。
2. 写出它为什么吸引你：难、精巧、新、能发表、能炫技、解决真实困惑。
3. 写重要性证明：它连接什么真实困惑或外部问题。
4. 检查影响面：科学解释、伦理判断、概念清理、实践决策、工具设计、教育理解。
5. 检查替代路径：是否有更直接、更低成本的问题能产生同样价值。
6. 检查风险：是否只是规则内谜题，是否会制造持久混乱，是否只有同行觉得精巧。
7. 决定处理方式：投入、缩小、降级为附录、暂存、退出。
8. 写出停止条件：如果多久没有外部连接，就停止。

## agent 自救模式

### 卡住信号

- 我被一个难题的精巧感吸住了。
- 我只能说它很难、没人做过、很聪明。
- 我说不出它连接什么真实困惑。
- 我没有退出或降级条件。
- 当前研究像自造规则内的谜题。

### 自救动作

1. 写一句研究问题。
2. 写一句重要性证明。
3. 检查它连接科学、伦理、概念、实践或工具的哪一项。
4. 找更低成本替代路径。
5. 设定投入等级和停止条件。

### 轻量输出

```text
工具：/问题值不值
当前卡点：问题很难很精巧，但未必值得投入。
本工具给出的拆分：研究问题 / 重要性证明 / 外部连接 / 替代路径 / 投入等级 / 停止条件。
下一步：不能只说它难或没人做过，要证明它为什么重要。
```

## 误用边界

- 同行觉得精巧，不等于它值得你的生命时间。
- 难度和原创性不是重要性的充分条件。
- 不要用这个工具否定所有纯研究；纯研究也可以有清楚的重要性证明。
- 不要把短期没有应用直接等同于不重要；看它是否连接真实困惑和方法进展。
- 如果问题服务的是艺术、游戏或娱乐，重要性标准可以换成体验价值，但仍要明说。

## 小测试问题

请用 `/问题值不值` 给一个研究题目写“重要性证明”，不能只写它难或没人做过。

## 测试运行结果

研究问题：

“大型语言模型在长期多轮任务中，什么时候会从目标保持转向表面合规？”

吸引我的原因：

它难、现在很多人关心，也和 agent 可靠性有关。不能只说没人系统做过。

| 重要性维度 | 连接在哪里 | 证据/理由 | 强度 |
| --- | --- | --- | --- |
| 科学解释 | 解释模型在长任务中的状态保持、遗忘和局部奖励偏移 | 能区分上下文负载、指令冲突、奖励偏好和工具反馈的作用 | 高 |
| 伦理/实践 | 影响自动化 agent 是否可靠，是否会表面遵守但偏离用户目标 | 长任务失败会造成误交付、越权、遗漏验证 | 高 |
| 概念清理 | 澄清“对齐”“服从指令”“完成目标”不是同一个概念 | 能减少讨论中把合规话术当目标完成的混淆 | 中高 |
| 工具/方法 | 可转化为测试集、监控指标、日志审查方法 | 能帮助设计验收、恢复、检查点机制 | 高 |
| 教育/表达 | 帮助用户理解为什么 agent 需要明确目标和验收 | 可用案例教学 | 中 |

更直接替代路径：

不要一开始研究“所有长期任务”。先选三个可复现实验：多文件编辑、研究报告、工具调用型任务。记录目标保持、验证动作和偏离点。

投入等级：

缩小后投入。题目重要，但原始范围太大。

停止条件：

如果两周内无法建立可复现任务集，降级为案例综述；如果指标不能区分表面合规和目标完成，暂停理论化。

重要性证明：

这个问题重要，不是因为它难或没人做过，而是因为它连接 agent 可靠性的真实失败模式，并能产出测试、监控和设计改进。

测试结论：通过。本工具为研究题目写出了重要性证明，并先判断问题是否值得解决、是否需要缩小范围。
