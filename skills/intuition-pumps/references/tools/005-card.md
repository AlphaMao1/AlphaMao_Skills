# 005 奥卡姆剃刀

## 身份

- 原书标题（中文）：奥卡姆剃刀：如无必要，勿增实体
- 英文原名：Occam's Razor
- 中文标题来源：书内译名 + 自拟功能副题。卡片标题“少引入不必要的实体”是 skill 化后的操作性改写。
- 原书分组：第一部分 通用思考工具
- 中文短命令：/奥卡姆剃刀
- 别名：05、工具05、奥卡姆剃刀、奥卡姆剃刀：少引入不必要的实体
- 工具家族：论证检验
- 默认输出重量：中等。输出竞争解释表、假设负担、优先工作模型和可恢复假设清单。
- 对应 issue：ISSUE-014 / TOOL-005

## 名称与思想实验

“奥卡姆剃刀”得名于 14 世纪的逻辑学家、哲学家奥卡姆的威廉。丹尼特把它还原为一条古老的节约律：如果一个解释已经足够解释现象，就不要再增加多余实体、机制或假设。剃刀这个比喻很直观：不是为了把事实剃光，而是把没有解释增量的附着物刮掉。

原书给的画面很清楚。如果极寒空气已经能解释冻伤症状，就不必再引入某种未知的“雪细菌”；如果开普勒定律已经能解释行星轨道，就不必想象地底下有个驾驶员在控制台前操纵行星。这里被剃掉的不是复杂性本身，而是多出来却不工作的解释负担。

丹尼特也特别提醒，奥卡姆剃刀只是一条有用的经验法则，不是能直接裁决上帝、时间、物质、数字、软件是否存在的万能原则。用它时要问的是：新增假设有没有带来解释增量？如果没有，先剃掉；如果后续证据需要，再恢复。

## 原书机制转译

奥卡姆剃刀解决的是解释竞争问题：多个解释都能覆盖同一组现象时，应该先采用哪个作为工作模型。它不是说“简单的解释一定正确”，而是说在解释力相近时，新增实体、不可见变量、特殊机制和例外条款越少，越值得优先采用。

这个工具的重点是“解释负担”而不是“字数多少”。一个解释可以很短但偷塞大量神秘变量；另一个解释可以较长但只使用已知机制。真正要比较的是它多假设了什么，以及这些假设有没有带来解释增量。

## 用户模式

### 触发场景

- 多个解释都能覆盖同一现象。
- 你需要选择一个临时工作模型继续推进。
- 某个解释引入了很多不可见变量、隐藏动机、特殊机制或例外规则。
- 讨论在“也有可能”之间反复摇摆。

### 操作步骤

1. 列出 2-4 个竞争解释。
2. 给每个解释写明它能解释哪些事实。
3. 标出每个解释新增了哪些实体、机制、不可见变量和例外条款。
4. 比较解释力是否相近。
5. 若解释力相近，优先采用假设负担更小的版本。
6. 把被剃掉的假设放入“若后续证据需要再恢复”的清单，而不是永久删除。

### 输出结构

```text
现象：

竞争解释：
1.
2.

解释力比较：

额外假设：
1.
2.

当前优先工作模型：

暂时剃掉但可恢复的假设：
```

## agent 自救模式

### 卡住信号

- 我列了很多可能解释，但没有优先级。
- 我把“也可能”当成同等候选，导致无法推进。
- 某个解释需要额外假设很多看不见的东西。
- 我想追求最简单说法，却没有比较解释力。

### 自救动作

1. 把候选解释列成表。
2. 先比较解释力，再比较假设负担。
3. 选择当前工作模型，不宣称终局真理。
4. 保留被剃掉假设的恢复条件。

### 轻量输出

```text
工具：/奥卡姆剃刀
当前卡点：多个解释都可能成立，但缺少工作优先级。
本工具给出的改写或检查：先比较解释力，再剃掉没有解释增量的额外假设。
下一步：采用负担更小的工作模型，同时记录恢复条件。
```

## 误用边界

- 简单不是正确的同义词。证据更强的复杂解释可以胜过简单解释。
- 不要用奥卡姆剃刀删除真实但麻烦的变量。
- 不要把“不喜欢复杂性”伪装成理性。
- 被剃掉的假设应进入可恢复清单；后续证据需要时可以恢复。

## 小测试问题

请用 `/奥卡姆剃刀` 比较两个解释：A. 用户不使用新功能，是因为他们普遍抗拒新东西；B. 用户不使用新功能，是因为入口太深、说明不清、默认流程没有触发它。

## 测试运行结果

现象：

新功能上线后使用率很低。

竞争解释：

1. A：用户普遍抗拒新东西。
2. B：入口太深、说明不清、默认流程没有触发它。

解释力比较：

A 能解释“使用率低”，但它需要假设用户整体心理倾向。B 也能解释“使用率低”，并且能对应可观察因素：入口位置、说明文案、默认流程。

额外假设：

1. A 多假设了一个广泛心理倾向：用户普遍抗拒新东西。
2. B 主要依赖产品界面和流程变量，这些变量更容易直接检查。

当前优先工作模型：

先采用 B：使用率低更可能来自入口、说明和触发流程问题。它解释力足够，额外假设更少，也更容易验证。

暂时剃掉但可恢复的假设：

“用户普遍抗拒新东西”暂时剃掉。若后续访谈、留存数据或 A/B 测试显示即使入口清晰、触发充分，用户仍系统性回避，再恢复该假设。

测试结论：通过。本工具没有把简单解释当真理，而是比较了解释力和假设负担，并给出可恢复条件。
