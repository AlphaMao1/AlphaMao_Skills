# 009 反话术

## 名称与思想实验

这张卡的原书标题把三种修辞动作称为 “Goulding”，是丹尼特用来指称斯蒂芬·杰伊·古尔德常用的三类“反思考”手法。这里的重点不是古尔德个人，而是三种会让读者滑过关键论证缺口的写法：`Rathering`、`Piling On` 和 `the Gould Two-Step`。

`Rathering` 对应中文里的“不如说”：它把 A 和 B 放成强转折，好像二者天然互斥，但常常没有证明这种互斥。`Piling On` 是“故意堆积”：把多个命题揉成一团，让读者以为作者反驳了整个包裹，其实可能只击中了其中一个较弱成分。`Gould Two-Step` 更微妙：先制造一个稻草人并驳倒，再把对方拿来澄清自己立场的证据解释成对方在攻击下退让。

所以短命令叫“反话术”：它不是禁止使用转折、强调或批评，而是把这些修辞重新拆成可检查命题。使用时要问：A/B 真互斥吗？被反驳的是哪个子命题？原文真的主张了这个靶子吗？对方是在改变立场，还是只是在指出你打错了靶？

## 原书机制转译

这个工具不是教你使用话术，而是教你识别会破坏思考的话术。危险不在转折词本身，而在它们常常偷偷完成三件事：把可并存的 A 和 B 说成互斥；把多个命题堆成一个含糊靶子；先制造弱靶，再把对方澄清说成退让。

作为 skill 命令，`/反话术` 的目标是把强转折拆回可检查命题。它要求你问：A 和 B 是否真的不能同时成立？作者到底反驳的是哪一个命题？对方原文是否真的主张了这个靶子？对方是在退让，还是只是在澄清原意？

## 用户模式

### 触发场景

- 你看到“与其说 A，不如说 B”“是 X 而不是 Y”“真正的问题不是……”这类强转折。
- 文章把多个观点压成一个含糊靶子。
- 争论中有人先夸张重写对方观点，再把对方澄清说成退让。
- 你想判断某段批评是否真的击中了原观点。

### 操作步骤

1. 把转折前后的 A、B 分别写成清楚命题。
2. 检查 A 和 B 是否真的互斥，还是可以同时成立。
3. 拆开堆积句，列出里面的多个子命题。
4. 核对对方原文是否真的主张这些子命题。
5. 如果对方后续澄清，判断这是修正立场，还是只是反驳稻草人。
6. 输出更公平的改写。

### 输出结构

```text
原话术：

A 命题：
B 命题：
是否互斥：

被堆积的子命题：
1.
2.

原文核对：

澄清还是退让：

更公平的改写：
```

## agent 自救模式

### 卡住信号

- 我被一句强转折带着走，但没有拆命题。
- 我准备接受“不是 A 而是 B”，却没检查 A/B 是否可共存。
- 我在反驳一个含糊总包，而不是具体命题。
- 我把用户澄清需求误读成改变立场。

### 自救动作

1. 把强转折拆成 A/B 两个命题。
2. 检查互斥关系。
3. 如果有堆积靶子，拆成子命题。
4. 核对原文或用户原意。
5. 输出公平改写，不继续沿用操纵性转折。

### 轻量输出

```text
工具：/反话术
当前卡点：强转折可能制造了虚假二分或稻草人。
本工具给出的改写或检查：拆 A/B 命题，检查是否互斥，并核对原文靶子。
下一步：把批评改成针对具体命题。
```

## 误用边界

- 这是一套诊断工具，不是写作模板。
- 不要因为出现“不是……而是……”就自动判定有问题。只有当它替代论证或制造互斥幻觉时才危险。
- 不要用“你这是话术”逃避实质反驳。拆完命题后仍要回到证据和逻辑。
- 不要把对方澄清一律说成退让。

## 测试运行结果

原话术：

“不是实现效率，而是 agent 有没有真正理解工具；所以任何提高效率的做法都应该被排除。”

A 命题：

项目需要考虑实现效率。

B 命题：

项目需要确保 agent 真正理解每个工具。

是否互斥：

不互斥。效率和理解可以同时成立。真正冲突的是“用效率做理由跳过逐卡理解”，而不是效率本身。

被堆积的子命题：

1. 项目核心问题是理解质量。
2. 提高效率会伤害理解质量。
3. 所有效率做法都应该排除。

原文核对：

前两点可能有条件成立；第三点过度升级。用户反对的是脚本批量生成工具卡，不是反对所有结构化流程、模板或验证命令。

澄清还是退让：

如果用户说“不能用脚本批量处理工具卡，但可以用检查命令验证”，这是澄清边界，不是退让。

更公平的改写：

本项目可以保留模板、索引和验证检查来提高一致性；但每张工具卡的机制转译和小测试必须逐卡完成，不能用效率作为批量生成的理由。

测试结论：通过。本工具拆开了强转折中的 A/B 命题，发现它们并不互斥，并把过度升级的结论改成了更准确的边界。
