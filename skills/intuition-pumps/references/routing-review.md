# Routing Review

本文件属于 `ISSUE-005`。它定义路由推荐规则和输出模式，不转译任何单张工具卡。

## 路由输入

路由前先把用户问题压缩成一句：

```text
当前问题：用户正在卡在……
```

再判断问题主要落在哪一类：

- 论证问题：命题、前提、反驳、批评、公平重述。
- 概念问题：边界、二分、层级、分类、变量。
- 解释问题：机制跳步、聪明小人、魔法词、复杂系统。
- 视角问题：系统内外、常识/科学、意向立场。
- 进化问题：设计感、选择、信号、物种、文化复制。
- 意识问题：体验、僵尸、感受质、第一人称报告、身份。
- 自由责任问题：决定论、选择、公平、责任。
- 元认知问题：问题值不值得、如何读、如何对待直觉。

## 固定 5 槽位

每次路由必须输出 5 个候选，不能少，不能多：

| 槽位 | 作用 |
|---|---|
| `most_relevant` | 最直接匹配当前问题的工具。 |
| `different_family` | 同一个问题的不同家族替代路径。 |
| `concept_boundary` | 澄清概念、层级、边界或变量。 |
| `counterintuitive_breakout` | 打破误导性直觉或默认框架。 |
| `low_frequency_explorer` | 低频但适配的探索工具。 |

## 推荐格式

```text
建议先用
- 工具：
- 原书标题 / 英文原名（如有）：
- 名字在书里的背景：
- 为什么这个名字对应当前动作：
- 槽位：
- 家族：
- 工具实际做什么：
- 理由：
- 不适用边界：
- 当前状态：可应用 / 卡片未完成

可选探索
1. 工具：
   - 原书标题 / 英文原名（如有）：
   - 名字在书里的背景：
   - 为什么这个名字对应当前动作：
   - 槽位：
   - 家族：
   - 工具实际做什么：
   - 理由：
   - 不适用边界：
   - 当前状态：可应用 / 卡片未完成
```

## 候选工具的解释要求

路由菜单不是命令清单。每个候选都必须先从自己的工具卡读取 `身份`、`名称与思想实验` 和 `原书机制转译`，再填写上面的字段；5 张卡要逐张、独立处理，不能只读索引后批量套用同一套解释。

“名字在书里的背景”至少回答三个问题：

1. 原书里出现了什么具体画面、故事、思想实验或术语？
2. 这个画面暴露了什么直觉陷阱或解释问题？
3. 为什么当前 skill 命令保留这个名字，使用时要对什么动手？

如果卡片名称是书内标题，而短命令是为了操作性自拟的，必须把两者分开说明：不能把自拟短命令伪装成书中的原名，也不能只解释短命令而不还原书中背景。

## 菜单模式

菜单模式只推荐，不自动应用。

触发词包括：

- 推荐几个工具
- 我不知道用哪个
- 帮我选几个直觉泵
- 这个问题适合什么思考工具

逐张读取 5 个候选卡片并输出完整候选说明后停止，等待用户选择。

## 推进模式

推进模式先推荐，再尝试应用 `建议先用`。

触发词包括：

- 我卡住了
- 帮我想想
- 直接处理
- 你来推进

如果 `建议先用` 的工具卡已经完成，保留菜单中已经给出的身份解释，必要时重新读取该单张卡并应用。

如果卡片未完成，停止在推荐菜单，并说明需要先完成对应工具卡 issue。不要从记忆补写工具卡。

## 点名调用的相邻推荐

点名调用优先尊重用户指定的工具。只有在以下情况才补充相邻工具：

- 指定工具只能处理问题的一半。
- 相邻工具能明显改变下一步验证动作。
- 用户要求比较或替代。

相邻工具最多推荐 2 个。

## 防塌缩规则

- 不要让 5 个候选都来自同一家族。
- 高频工具被推荐时，必须说明为什么这次仍然该用它。
- `low_frequency_explorer` 必须优先考虑不显眼但结构适配的工具。
- 如果最相关工具是高频工具，`different_family` 和 `low_frequency_explorer` 应主动拉开距离。
- 如果候选无法覆盖多个家族，说明原因，而不是硬凑。

## 卡片状态规则

路由可以使用 `tool-index.json` 推荐工具；应用工具必须读取对应工具卡。

- `references/tools/NNN-card.md` 存在且内容完成：可应用。
- 卡片不存在：只能推荐，不能应用。
- 卡片存在但缺少小测试或测试结果：视为未完成。
