# Agent Self-Rescue

本文件属于 `ISSUE-006`。它定义 agent 自救入口、触发信号、输出结构和显式说明边界。

## 什么时候可以触发

只有出现明确卡住信号时才触发：

- 同一路径连续推进两次，没有新证据、新区分或新下一步。
- 解释依赖一个魔法词，例如“智能”“意识”“本质”“价值”“系统会自己处理”，但没有说明机制。
- 概念边界反复滑动，例如对象/描述、事实/评价、规则/行为、决定/公平。
- 论证绕回原句，只是在换词复述。
- 当前问题需要一个小的可检查输出，但 agent 只给了抽象判断。

## 什么时候不能触发

- 只是任务复杂。
- 只是需要更多文件、日志、测试或事实证据。
- 用户明确要求不要使用思考工具。
- 工具卡尚未完成，且当前动作需要应用该工具。
- 会把工程调试、事实核查或高风险执行替换成哲学讨论。

## 自救流程

1. 写一句内部问题压缩：`我卡在……`
2. 用 `routing-review.md` 选择一个工具，不超过一个。
3. 检查对应工具卡是否存在且完成。
4. 如果工具卡不存在，只能报告被哪个工具卡 issue 阻塞。
5. 如果工具卡存在，读取该单张卡并轻量应用。
6. 产出下一步动作，不输出长篇学习说明。

## 轻量输出

```text
工具：
原书名字背景 / 当前命令对应关系：
当前卡点：
本工具给出的改写或检查：
下一步：
```

这里的“原书名字背景 / 当前命令对应关系”只需一两句：说明书中那个故事、思想实验或术语画面，以及它为什么对应当前自救动作。不能只输出一个用户未必认识的短命令。

## 什么时候显式告诉用户

只有当自救改变了以下任一项时，才显式说明使用了工具：

- 推理路径
- 结论强度
- 取舍依据
- 下一步动作
- 对风险或不确定性的判断

如果只是内部整理，不需要表演过程。

## 阻塞输出

当自救选中的工具卡尚未完成时：

```text
我识别到一个适合用 [工具名] 的卡点，但这张工具卡还没有实现。
当前只能说明阻塞：需要先完成 [ISSUE-xxx / TOOL-xxx]。
我不会从记忆补写或临时生成这张卡。
```

## 防滥用

- 自救不是常规推理装饰。
- 自救不是把每个问题哲学化。
- 自救不能绕过测试、日志、事实核查或用户授权。
- 自救不能批量生成工具卡。
