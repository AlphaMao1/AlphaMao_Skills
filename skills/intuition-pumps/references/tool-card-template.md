## 名称与思想实验

解释这个工具为什么叫这个名字：原书里的故事、思想实验、比喻或术语是什么；读者需要知道哪一个画面，才能理解这个名字和工具动作之间的关系。

本节只做必要背景解释，不复制原书大段正文。写完后读者应该能回答：“为什么这个名字对应这个操作？”

## 原书机制转译

写清楚这个工具原本解决什么认知问题，以及它怎样把问题变成可执行的思考动作。

不得只复述标题。不得复制原书大段正文。

## 用户模式

### 触发场景

写清楚用户在什么问题状态下应该调用这个工具。

### 操作步骤

写成用户可以照着做的步骤。步骤必须产生可检查输出。

### 输出结构

说明使用本工具后应该交付什么，例如命题改写、前提表、变量旋钮、机制链、反例、边界判断或下一步验证动作。

## agent 自救模式

### 卡住信号

写清楚 agent 在什么卡点下可以主动使用本工具自救。

### 自救动作

写清楚 agent 如何轻量应用本工具，并且只处理当前工具，不顺手切换或补写其他工具。

### 轻量输出

```text
工具：
当前卡点：
本工具给出的改写或检查：
下一步：
```

## 误用边界

写清楚什么时候不该用这个工具，以及它容易制造什么错觉。

## 小测试问题

设计一个服务该工具真实用途的小测试问题。测试问题必须能检验该工具是否真的可操作。
