# Phase 2: 分镜规划

## 核心原则：建立帧/效果帧必须成对出现

**建立帧（Establishing Frame）**：展示完整、干净的 UI，动态密度极低，让观众理解「这是什么」。

**效果帧（Effect Frame）**：在建立帧的基础上叠加动态效果（弹出、飞入、推镜等），动态密度高。

**规则**：每个效果帧前面**必须**有对应的建立帧，否则观众不知道在看什么，视频模型也无法生成平滑过渡。

> 反例：直接从建立帧 A 切到效果帧 B（A 和 B 是不同 UI）——这是跳切，不是过渡。

## 视觉盲点定律（过渡设计的核心原理）

**核心命题**：内容切换必须发生在「视觉盲点」内——即两张图片之间存在一个两者都不可辨认的中间状态。没有盲点，就会跳切。

视频模型通过物理连续性插帧，它不理解「故事」，只模拟「物理」。好的过渡让模型**永远不需要回答「A 是怎么变成 B 的」**，因为在 A 和 B 之间，有一段视觉上什么都看不清的盲点——模型只需要模拟「A 进入盲点」和「B 从盲点出来」，这两段都是物理上可解的。

### 制造盲点的三种方式

| 盲点类型 | 物理机制 | 典型实现 | 质量 |
|---|---|---|---|
| **几何遮挡盲点** | 物体运动到「主面朝侧方」的瞬间，正反两面内容均不可见 | 翻转、门轴旋转、物体飞出画框后画面清空 | ⭐⭐⭐ 最佳 |
| **运动模糊盲点** | 高速运动时帧间细节糊掉，模型容忍细节不一致 | 推镜穿过物体表面、爆炸式拉远、快速划过 | ⭐⭐ 良好 |
| **曝光覆盖盲点** | 强光或纯黑充满画面，旧内容消失，新内容从中浮现 | 推镜到纯黑深处、镜头光斑、闪白 | ⭐⭐ 良好 |

### 最优解：几何遮挡盲点「翻转切换法」

V11 中效果最好的过渡是 F1→F2 的翻转：面板翻到侧面那一刻，两侧都不可见，切图片在这个瞬间发生，F2 的另一套 UI 从「背面」翻出来。模型处理的任务是「一块面板在翻转」，完全可解，**甚至不需要黑帧**。

**翻转的本质可推广到任何「主面消失」动作**，不局限于字面上的翻转：

| 동作 | 盲点时机 | 提示词关键描述 |
|---|---|---|
| 水平/垂直翻转 | 侧面朝镜头的瞬间 | `the panel flips revealing its back face which shows [新UI]` |
| 旋转门式 | 边缘朝镜头的瞬间 | `the screen rotates like a revolving door, the opposite face emerges with [新UI]` |
| 整体飞出画框 | 画面完全清空后 | 整个载体飞出 → 画面空白 → 新载体飞入，等同翻转的黑帧版 |
| 镜头推入纯黑表面 | 画面全黑时 | `camera dives into the dark surface until the frame goes completely black, then pulls back to reveal [新场景]` |
| 大面积物体扫过 | 物体遮住全画面时 | 前景物体从左扫到右，扫过画面的瞬间背景已换 |

### 失败模式：「可见区域内的内容替换」

飞出效果（V11 第二部分）的问题本质：图标飞出后，**背景面板依然静止可见**，然后图标消失、新内容原地出现——从未有过一个盲点，A（面板+图标）直接替换为 B（面板+新内容），模型无法插帧。

根本区别：
- ✅ 翻转：切换发生在**盲点内**（侧面朝镜头时，没有人看到切换）
- ❌ 飞出+原地替换：切换在**可见区域内**发生（所有人都能看到这里有个不自然的替换）

**修复原则**：任何效果帧的「离场」，都必须让**承载底层内容的载体本身**也参与退场。只让浮在上面的效果元素消失，留着底部静止的主载体，必然跳切。

### 自检问题

写每个部分的过渡时问自己：
1. **盲点在哪里？** 两张图片之间，哪一帧是「什么都看不清的状态」？
2. **是谁在退场？** 只有表面效果元素在退场，还是主载体本身也在退场？
3. **切换时机对吗？** 图片切换是在运动最快/遮挡最深的那一刻发生的吗？

## 2.1 标准帧序列模板（10帧版）

```
F1  [建立帧] UI-A 全景展示
F2  [过渡帧] UI-A 折叠退场（同一载体翻转/滑出）
F3  [建立帧] UI-B 全景展示
F4  [效果帧] UI-B 上的动效（破屏弹出、卡片飞入等）
F5  [建立帧] UI-C 全景展示
F6  [效果帧] UI-C 上的动效
F7  [建立帧] UI-D 全景展示
F8  [效果帧] UI-D 上的动效（通常是微距 close-up）
F9  [建立帧] 失重全景（多个载体同时漂浮）
F10 [效果帧] 粒子解体谢幕
```

## 2.2 过渡类型清单

| 过渡类型 | 触发时机 | 离场出口 | 说明 |
|---|---|---|---|
| **折叠退场** | F1→F2 | ✅ 运动出口 | 翻转→侧面→飞出，画面清空后硬切 |
| **砸入浮现** | 硬切后→新建立帧 | （接收端，不需要出口） | 新载体从下方以运动状态进入，有活力 |
| **破屏弹出** | 建立帧→效果帧 | ⚠️ 需要补出口 | 图标飞散后加「镜头快速拉后」等出口动作再切 |
| **卡片流入** | 建立帧→效果帧 | ⚠️ 最容易跳切 | 卡片停稳后是危险区！需要补「镜头穿过卡片群」或「卡片收回」动作 |
| **微距推镜** | 建立帧→效果帧 | ✅ 运动出口 | 推镜动作本身就是出口；点击涟漪消散后的「爆炸拉远」是完美出口 |
| **爆炸拉远** | 效果帧→失重全景 | ✅ 运动出口 | 拉远动作连接前后，空间连续 |
| **粒子解体** | 失重全景→谢幕 | ✅ 自带出口 | 粒子扩散→画面渐黑，自然结束 |

## 2.3 动效密度控制

参考三类视频的节奏规律：
- **建立帧**：动态密度极低，镜头悬停，让 UI 内容清晰可读
- **效果帧**：动态密度高，但**同一帧只做一件事**（不要同时有多个复杂效果）
- **过渡帧**：动态密度中，专注运动本身，不承担信息展示任务

**运动预算原则**：一个 clip 内，运镜 + 主体动作 + 环境动态的复杂度总和有限。如果效果很复杂，就让镜头保持不动（或反之）。

## 2.4 分镜规划输出格式

以 Markdown 表格形式输出分镜规划，包含：

| 帧 | 类型 | UI来源 | 效果描述 | 垫图来源 | → 过渡方式 |
|---|---|---|---|---|---|
| F1 | 建立帧 | UI-A截图 | 载体居中悬浮，完整展示 | 风格参考图 + UI-A截图 | 同物体翻转退场 |

在动手生成图片前，先把完整分镜表写出来，让用户确认逻辑再执行。
