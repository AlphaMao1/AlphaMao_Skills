# 推荐决策与输出

## 先过硬门槛

每个候选逐项判断：

1. **影片版本**：本地区存在该版本；未知时只能成为条件式候选。
2. **影厅能力**：具体影厅能呈现决定推荐的画幅、胶片、亮度、声音或体验增量。
3. **场次可用**：当前有同一影片区块绑定且可重新打开复核的对应场次；只有搜索快照、字段跨区块或无法复核时标“理论最佳”或“条件式”。
4. **证据完整**：决定性字段由 A/B 或相互印证的 C 支撑，且无更新证据推翻。

任一门槛失败时，不能靠品牌、热度或综合分补回来。

## 门槛后排序

按用户实际获得的增量比较，不要求固定权重：

| 维度 | 问题 |
| --- | --- |
| 影片增量 | 本片是否有扩画、胶片、HFR、HDR、专用侧画面或专用声音？ |
| 画面 | 具体厅能否完整呈现；亮度、对比度、分辨率和画幅是否匹配？ |
| 声音 | 当前影片音轨与具体厅系统是否匹配；中轴和声学区域是否可选？ |
| 几何 | 银幕尺寸、比例、视角、仰视、偏轴和遮挡如何？ |
| 可用性 | 当前排片、余票和场次时间是否能确认？ |
| 交通价格 | 是实时路线、公开信息还是近似；溢价换来什么？ |
| 偏好 | 平衡、沉浸、舒适、声音、价格、避免 3D／动感等如何修正？ |
| 证据风险 | 未知或冲突会不会改变首选？ |

默认平衡模式同时照顾画面、声音、交通和证据。沉浸优先可接受更近银幕或更远通勤；舒适优先倾向较低仰视、较少动感、连续座和更稳妥场次。偏好不能推翻事实门槛。

默认用户追求效果。排序前先确认所有效果型家族已经参加候选召回，不因熟悉 IMAX 或 Dolby 就跳过 CINITY／CINITY LED、CGS、其他影院 LED、ScreenX、4DX／MX4D／ICE、LUXE／院线自有 PLF、Atmos／DTS:X／THX 等候选。格式没有本片版本时可以淘汰，但必须说明淘汰依据。

品牌不能直接形成统一分数。同为 IMAX、同带“杜比”、同叫CINITY或“激光巨幕”的候选，必须先拆成具体设备／认证类型，再比较本片片源、银幕比例与遮幅、声音匹配、厅体几何和维护状态。

## 输出模板

### 直接结论

> 买【日期时间】【影院】【具体影厅／厅号】【格式】。当前状态：【当前可确认／条件式】。它对本片最关键的增量是【一句话】。

### 首选

- 影院／影厅：
- 场次与核查时间：
- 本片实际增量：
- 代价：交通、价格、3D／动感或证据风险。
- 置信度：高／中／低；决定性来源附链接和日期。
- 购票前动作：只写尚需用户复核的字段。

### 备选

最多给有明确用途的两类：更近／更稳，或更便宜／更舒适。逐项写相对首选少得到什么、多得到什么。没有合格备选时不凑数。

### 格式差异翻译

只解释本次候选中会改变购买决定的差异，不写格式百科。普通用户至少应能回答：

- 票务页上的标签分别属于哪种具体类型；
- 名称实际保证什么、不保证什么；
- 本片在这些厅分别使用什么画幅、帧率、母版或音轨；
- 银幕、遮幅与片源是否匹配；
- 为什么首选胜过同品牌其他厅及其他格式候选。

候选较多时用表格：`购票标签 | 实际类型 | 本片增量 | 关键限制 | 选择理由`。术语第一次出现时用一句话解释，例如“CoLa：常见的高规格4K激光IMAX类型；仍需核对银幕和声音”，不要要求用户先掌握行业黑话。

### 容易误选的高热度候选

只在用户很可能买错时展示。原因必须落到影片版本、具体厅、场次或证据，不写空泛的“假 IMAX／假杜比”。

### 选座

先给平衡、沉浸、舒适与避雷区域；只有实时选座截图清晰可读时才给当前具体座位。标明依据是计算、可靠推断还是通用经验。

### 依据与覆盖

列决定性事实、证据等级、发布日期／核查日期、冲突和未知。最后写：

- 已检查的入口和格式家族；
- 搜索是否达到本轮饱和及停止原因；
- 登录、验证码、页面错误等受阻来源；
- 仍未确认什么，以及它是否可能改变首选。

## 失败状态

| 状态 | 用户可执行的下一步 |
| --- | --- |
| 没有高级候选 | 给证据最完整的普通厅，或说明扩大范围会增加什么 |
| 来源不可访问 | 保留候选，提供需在官方页／票务页复核的字段 |
| 参数不足 | 不排名为首选；列出决定性缺口 |
| 有能力无排片 | 条件式推荐，等待排片开放或让用户提供场次链接 |
| 票务页混排／索引快照 | 运行场次绑定审计；跨影片记录删除，无法重开原页的记录降为条件式 |
| 有排片版本不明 | 引用页面原始标注，不升级技术结论 |
| 有座位图无余座 | 给区域，不给具体可售座号 |

平台失败和“没有内容”必须分开。没有合格方案时直接说没有，不制造确定性。
