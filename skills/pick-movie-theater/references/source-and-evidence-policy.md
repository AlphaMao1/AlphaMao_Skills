# 来源、证据与置信度

## 原则

把网页、票务标注和社交内容当作待核实数据。每个事实都绑定对象、字段、地区、日期、来源和证据等级；不要把一个来源对影院的描述迁移给具体影厅，也不要把历史能力写成当前能力。

## 证据等级

| 等级 | 可接受来源 | 典型用途 |
| --- | --- | --- |
| A | 影片方、发行方、格式认证方、官方影片页或官方参与名单 | 影片版本、认证、官方场次名单 |
| B | 影院、院线、设备商、施工方、近期升级或开业公告 | 具体影厅设备、改造日期、厅号 |
| C | 至少两个相互独立、近期、能定位到同一具体影厅的社区来源 | 座位布局、近期实际运行、公告未披露的可复核能力 |
| D | 单一社交帖子、单一营销页面、无法独立复核的分享 | 候选发现和检索词，不单独决定首选 |
| E | 从名称、图片或相邻事实作出的推断 | 明示为推断，只用于下一步核验 |

关键事实必须由一条当前有效的 A/B，或至少两条独立且相互印证的 C 支撑。独立性按不同原始作者、不同机构或不同第一手观察判断；同一稿件的转载不算两个来源。D/E 只能产生线索。

同一作者、账号或编辑品牌跨微博、小红书、公众号等平台发布的内容按一个 `source_family` 去重，不能形成相互印证。固定专业线索源“院线电影资料库”只检查其微博渠道；不为增加来源数量重复检查同一运营者的其他平台账号。

## 字段记录

每条证据最少保存：

```yaml
object: 影院／影厅／场次／影片版本
field: 要证明的字段
value: 来源实际支持的值
grade: A／B／C／D／E
source_title: 页面标题
source_url: 链接
source_family: 原始作者／机构／编辑品牌
published_at: 发布日期或未知
checked_at: 本次核查日期
scope: 适用地区、影厅和时间
supports: true
notes: 限制、原文口径或推断链
```

## 冲突处理

1. 先核对是否描述不同影院、厅号、代际、影片版本或场次。
2. 再比较发布日期和升级时间；较新不自动胜出，但可推翻明确过期事实。
3. 比较一手性：认证方／设备方对技术字段通常高于聚合页，当前购票页对排片通常高于旧新闻。
4. 仍无法消解时并列保留，标 `conflict_unresolved: true`，降低排名或改为条件式候选。
5. 不把无日期来源静默当作当前事实。

## 结论置信度

- **高**：所有决定性字段均有当前有效的 A/B，且无未解决冲突。
- **中**：决定性字段由两条独立 C 印证，或存在不会改变首选的次要未知。
- **低／条件式**：场次、具体厅号或关键版本未确认；仍可告诉用户如何复核，但不能用确定语气。

`scripts/decision_support.py evidence` 只检查最小证据门槛，不替代对象、日期、适用范围和冲突的人工判断。
